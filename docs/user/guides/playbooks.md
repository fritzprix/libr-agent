# Playbooks

> 사이드바 **Playbooks** (`/playbooks`).  
> 에이전트가 잘 끝낸 **복잡한 요청을 기록**해 두고, 같은 작업을 프롬프트 없이 다시 돌릴 때 씁니다.

---

## 만들기

앱 UI에 “빈 플레이북 작성” 위저드만으로 만들기보다, 대화에서 만드는 흐름이 기본입니다.

1. **Chat**에서 원하는 작업을 끝까지 수행합니다.
2. 에이전트에게 예를 들어 `Create a playbook` / `플레이북으로 저장해줘`라고 요청합니다.
3. 사이드바 **Playbooks** 목록에 나타납니다.

Empty state 안내도 같은 내용입니다: 에이전트에게 플레이북 생성을 요청 → 이후 **Start**로 재실행.

---

## 실행하기

1. **Playbooks**에서 항목을 찾습니다 (검색·정렬·북마크 가능).
2. 카드의 **Start**를 누릅니다.
3. 연결된 어시스턴트로 세션이 시작되며 기록된 단계/목표가 이어집니다.

입력에 `@playbook:` 멘션으로 참조할 수도 있습니다 (Scheduled Task 메시지 등에서도 동일 자동완성).

---

## 관리

- **Bookmark**: 자주 쓰는 플레이북 고정
- **Delete**: 확인 후 삭제 (복구 없음)
- 정렬: 생성일, 어시스턴트, 북마크 우선 등

---

## 스킬과의 차이

|          | Playbook                      | Skill (`@skill:`)         |
| -------- | ----------------------------- | ------------------------- |
| 무엇인가 | 성공한 **실행 기록**을 재실행 | `SKILL.md` **절차 문서**  |
| 만들기   | 대화 후 저장 요청             | skill-creator / 파일 배포 |
| 쓰기     | **Start** 또는 `@playbook:`   | `@skill:이름`             |

둘 다 쓸 수 있습니다. 반복 “워크플로 재실행”은 Playbook, “항상 같은 절차로 생각하라”는 Skill에 가깝습니다.
