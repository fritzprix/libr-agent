# 작업이 끝나면 이어서 진행

> `@skill:call-me-back`은 에이전트가 **작업이 끝나기를 기다렸다가**, 끝나면 **같은 대화에서 이어서** 일하게 합니다.  
> 에이전트는 시간을 짐작하지 않습니다. 실제로 "끝났다"는 신호를 기다립니다.

---

## 이 스킬이 하는 일

LibrAgent의 원칙은 **추측하지 않고 확인한다**는 것입니다. 그래서 "몇 분 뒤쯤 끝나겠지" 하고 짐작하지 않고, 실제로 끝났다는 신호를 기다립니다. 모든 일은 내 컴퓨터 안에서 일어납니다.

오래 걸리는 작업이 있습니다. 예: 빌드, 테스트, 데이터 내보내기, 사람이 닫아야 하는 티켓.

이런 작업을 계속 지켜볼 필요는 없습니다. 무엇을 기다릴지만 말해 주세요. 작업이 끝나면 에이전트가 **같은 대화**에서 결과를 보고 이어서 일합니다.

"call me back"의 "me"는 **이 대화 세션**입니다. 전화나 문자를 보내는 기능이 아닙니다.

---

## 어떤 스킬을 쓰나요?

| 하고 싶은 일                         | 스킬           | 예시                                   |
| ------------------------------------ | -------------- | -------------------------------------- |
| 작업이 **끝나기**를 기다림           | `call-me-back` | "빌드가 끝나면 알려줘."                |
| 정해진 **시간**에 이 대화로 돌아옴   | `loop`         | "30분 뒤에 다시 확인해줘."             |
| 앱을 닫아도 **일정**대로 실행        | `schedule`     | "매주 월요일 9시에 리포트를 만들어줘." |
| **다른 에이전트**에게 지금 일을 맡김 | `delegate`     | "리뷰어에게 이 파일을 검토시켜줘."     |

기준: **작업·명령·도구**의 이름을 말하면 `call-me-back`입니다. **시각**만 말하면 `loop`입니다.

---

## 경우 1: 내 컴퓨터에서 도는 작업

가장 쉬운 경우입니다. 에이전트가 작업을 시작하고 직접 기다립니다. 따로 설정할 것이 없습니다.

```text
@skill:call-me-back
전체 테스트를 백그라운드로 실행해줘.
끝나면 실패한 테스트와 원인을 알려줘.
```

진행 순서:

1. 에이전트가 작업을 백그라운드로 시작합니다.
2. 작업이 멈출 때까지 기다립니다. 계속 반복해서 확인하지 **않습니다**.
3. 작업의 출력을 읽습니다.
4. 이 대화에서 결과를 알려 줍니다.

> **참고**: 대화창을 열어 두거나 다른 화면에서 작업해도 됩니다. 작업이 멈추면 에이전트가 이어서 진행합니다.

---

## 경우 2: LibrAgent 밖의 도구

웹훅, 파일 감시 도구, 빌드 서버 같은 도구에 쓰는 경우입니다. 이런 도구는 작업이 끝나면 **이 대화로 메시지를 보내야** 합니다.

```text
@skill:call-me-back
빌드 서버에서 배포 작업이 돌고 있어.
작업이 끝나면 이 대화로 메시지를 보내도록 빌드 서버를 설정해줘.
그다음 기다렸다가 배포가 성공했는지 알려줘.
```

진행 순서:

1. 에이전트가 **이 대화의 주소**를 찾습니다. 이 대화에서만 쓰는 주소이며, 내 컴퓨터 안에서만 동작합니다.
2. 작업이 끝나면 그 주소로 짧은 메시지를 보내도록 외부 도구를 설정합니다.
3. 에이전트가 기다립니다.
4. 외부 도구가 메시지를 보냅니다. 에이전트가 이 대화에서 이어서 일합니다.

### 메시지가 대화에 도착해야 합니다

외부 도구가 대화 주소로 메시지를 보내기 전에는 설정이 **끝난 것이 아닙니다**.

글자만 출력하거나 파일에 저장만 하는 도구는 대화를 이어 주지 **못합니다**. 에이전트가 그 글자를 볼 수 없습니다.

> **주의**: 글자만 출력하거나 파일만 저장하는 콜백은 쓰지 마세요. 대화는 계속 기다리고, 아무 일도 일어나지 않습니다.

### 안전

- 대화 주소는 **내 컴퓨터 안에서만** 동작합니다. 다른 컴퓨터는 쓸 수 없습니다.
- 주소는 세션마다 다릅니다. 다른 사람에게 알려 주지 마세요.
- 인터넷의 낯선 웹 페이지가 이 주소로 메시지를 보낼 수 없습니다.

## 요청에 쓸 내용

좋은 요청에는 세 가지가 있습니다.

| 항목                | 예시                                            |
| ------------------- | ----------------------------------------------- |
| **무엇을 기다리나** | "빌드 서버의 `deploy` 작업"                     |
| **끝난 뒤 할 일**   | "성공했는지 알려주고 로그 마지막 20줄을 보여줘" |
| **실패하면**        | "실패하면 원인을 찾고 해결책을 제안해줘"        |

---

## 흔한 실수

| 문제                                         | 원인                                                       | 해결                                                       |
| -------------------------------------------- | ---------------------------------------------------------- | ---------------------------------------------------------- |
| 에이전트가 "5분 뒤에 다시 확인할게요"라고 함 | 완료 신호(`call-me-back`)가 아니라 시간(`loop`)으로 처리함 | 작업 이름을 말하고 "작업이 끝날 때까지 기다려줘"라고 요청  |
| 외부 작업이 끝났는데 아무 일도 없음          | 외부 도구가 대화로 메시지를 보내지 않음                    | 도구가 대화 주소로 메시지를 보내는지 에이전트에게 확인시킴 |
| 외부 도구에서 주소 오류가 남                 | 주소가 틀리거나 앱을 다시 시작함                           | 에이전트에게 현재 주소를 묻고 도구를 다시 설정             |
| 기다리는 시간이 너무 김                      | 작업이 매우 오래 걸림                                      | 앱을 닫아도 돌아야 하면 `schedule` 사용                    |
| 알림만 필요했음                              | 알림은 시간 기반                                           | `loop` 사용: "10분 뒤에 알려줘."                           |
