# Refactoring Plan: Legacy Web MCP Tool Restoration & Migration

**Date:** 2025-12-28  
**Target Version:** 0.4.0  
**Priority:** CRITICAL  
**Status:** Planning

---

## 목적 (Purpose)

Legacy Web MCP (TypeScript)에서 Rust Builtin MCP로 마이그레이션하는 과정에서 **29개 도구가 누락**되고 **18개 도구의 스펙이 변경**된 문제를 해결합니다.

**핵심 목표:**

1. **완전한 기능 복원**: 삭제된 모든 도구(Planning, Playbook, MCP Manager 등)를 Rust에서 재구현하여 Legacy와 동일한 기능을 제공합니다.
2. **스펙 일치**: 도구 이름, 파라미터 스키마, 응답 형식을 Legacy와 100% 일치시켜 기존 프롬프트 및 워크플로우와의 호환성을 보장합니다.
3. **인프라 복구**: 누락된 MCP Manager 서버를 구현하여 동적 서버 등록 및 관리 기능을 복구합니다.

---

## 현재 상태 / 문제점

### 1. 도구 대량 누락 (Critical)

총 47개 Legacy 도구 중 **29개(62%)가 Rust 구현에서 누락**되었습니다.

- **Planning Server**: 14개 도구 삭제 (Nested Todo, Scratchpad 고급 기능, 메타인지 도구 등)
- **MCP Manager Server**: 서버 전체(5개 도구) 누락 (동적 서버 관리 불가)
- **Playbook Server**: 4개 도구 삭제 (복잡한 워크플로우 생성/수정 불가)
- **Knowledge/UI/Bootstrap**: 일부 도구 누락

### 2. 파라미터 스키마 불일치

마이그레이션된 18개 도구 중 다수가 스키마가 변경되어 호환성이 깨졌습니다.

- **Assistant**: 개별 필드(`name`, `systemPrompt` 등) 대신 단일 `config` JSON 객체 사용
- **Planning**: `createGoal`/`updateGoal` 대신 `setGoal`로 통합, Todo의 nested 구조 제거
- **Playbook**: 복잡한 Step 구조 대신 단순 템플릿 문자열 사용

### 3. 도구 이름 규칙 변경

- Legacy: `camelCase` (예: `promptUser`, `createGoal`)
- Rust: `snake_case` (예: `prompt_user`, `set_goal`)
- **문제**: LLM이 학습한 도구 이름과 달라 호출 실패 발생

## 관련 코드 구조 및 동작 방식 Summary (Bird's Eye View)

### Legacy Web MCP (TypeScript)

- **위치**: `src/lib/web-mcp/modules/*/server.ts`
- **특징**:
  - 유연한 JSON 스키마 (Nested Object 지원)
  - `MCPResponseBuilder`를 통한 풍부한 응답 (Rich Text + Structured Data)
  - 상태 관리: In-memory + IndexedDB (Dexie)

### Current Rust Builtin (Rust)

- **위치**: `src-tauri/src/mcp/builtin/*/mod.rs`
- **특징**:
  - `MCPServiceProxy`를 통한 중앙 라우팅
  - SQLite 기반 영구 저장소
  - 현재 단순화된 스키마와 응답 형식 사용

## 변경 이후 상태 / 해결 판정 기준

### 성공 기준

1. **모든 Legacy 도구 존재**: 47개 도구 모두 Rust에서 호출 가능해야 함
2. **스키마 100% 일치**: 파라미터 이름, 타입, 필수 여부가 Legacy와 동일해야 함
3. **응답 형식 일치**: `ResponseBuilder`를 사용하여 텍스트, UI 리소스, 가이던스 정보가 동일하게 반환되어야 함
4. **MCP Manager 동작**: Rust에서 `create_server`, `connect_server` 등이 정상 작동해야 함

## 수정이 필요한 코드 및 수정 부분

### Phase 1: MCP Manager Server 구현 (New)

**파일**: `src-tauri/src/mcp/builtin/mcp_manager/mod.rs` (신규 생성)

Legacy `mcp-manager`의 5개 도구를 Rust로 포팅합니다.

- `listServers`: 등록된 서버 목록 조회
- `searchServers`: 서버 검색 (BM25/Simple)
- `createServer`: 서버 설정 등록 (Stdio/HTTP)
- `connectServer`: Assistant에 서버 연결
- `disconnectServer`: 연결 해제

**구현 포인트**:

- `MCPServerManager` (Rust)와 연동하여 실제 서버 프로세스 관리
- `SessionMetadata` 업데이트를 통해 연결 상태 관리

### Phase 2: Planning Server 복원 (Heavy Refactoring)

**파일**: `src-tauri/src/mcp/builtin/planning/mod.rs`

**복원 대상**:

1. **Goal 관리**: `createGoal`, `updateGoal`, `clearGoal` (기존 `setGoal` 대체)
2. **Todo 관리**: `addTodo` (Nested 구조 지원), `checkTodo`, `clearTodos`
   - DB 스키마 변경 필요: `subtasks` (JSON), `priority`, `tags` 컬럼 추가
3. **Scratchpad**: `addScratchpad`, `listScratchpad`, `readScratchpad`, `clearScratchpad`
   - DB 스키마 변경 필요: `tags` (JSON), `source` 컬럼 추가
4. **메타인지**: `pauseAndThink`, `critiqueAndReflection`, `sequentialthinking`
   - LLM 호출이 필요한 도구는 Rust에서 `AgentSessionManager`를 통해 LLM 요청을 수행하거나, 단순 프롬프트 가이드를 반환하도록 구현

### Phase 3: Playbook Server 복원

**파일**: `src-tauri/src/mcp/builtin/playbook/mod.rs`

**복원 대상**:

1. **Workflow 스키마**: `createPlaybook`, `updatePlaybook`에서 복잡한 Step 구조 지원
   - DB 스키마: `workflow` 컬럼을 JSON 타입으로 확장
2. **UI 도구**: `showPlaybooks`, `getPlaybookPage` (Interactive UI 리소스 반환)

### Phase 4: Assistant Server 스키마 롤백

**파일**: `src-tauri/src/mcp/builtin/assistant/mod.rs`

**수정 사항**:

- `createAssistant`, `updateAssistant`: `config` JSON 파라미터를 개별 필드(`name`, `systemPrompt` 등)로 분리
- `searchAssistant`: BM25 검색 로직 구현 (SQLite FTS5 활용)

### Phase 5: 기타 도구 복원

- **UI**: `circuitBreak`, `resumeCircuitBreak` 구현
- **Knowledge**: `getKnowledge`, `deleteKnowledge` 구현, 태그 배열 지원
- **Bootstrap**: `checkToolInstalled` 구현

## Clarification Q-list

### Q1. Planning/Playbook DB 스키마 마이그레이션 전략

Legacy의 복잡한 구조(Nested Todo, Workflow Steps)를 지원하기 위해 SQLite 테이블에 JSON 컬럼을 추가해야 합니다. 기존 데이터를 보존하면서 마이그레이션하는 전략(예: `ALTER TABLE` vs `CREATE NEW & COPY`)을 어떻게 가져갈까요?

> 답변: 맞아. Legacy역시 indexedDb에서 이러한 상태 관리를 지원했어. 마이그레이션은 필요 없어. 아주 초기의 프로젝트임. 우선 기존 데이터는 버려져도 된다고 가정하자

### Q2. 메타인지 도구(pauseAndThink 등)의 Rust 구현 방식

Legacy에서는 이 도구들이 단순히 텍스트를 반환하거나 상태를 저장했습니다. Rust에서도 동일하게 상태 저장/반환만 수행하면 될까요, 아니면 실제 LLM 추론 프로세스(Chain of Thought)를 Rust 레벨에서 제어해야 할까요? (Legacy 동작을 그대로 복원한다면 전자)

> 답변: 동일하게 구현한다가 핵심이야. 더 발전시키는것은 나중에 제안해줘

### Q3. MCP Manager의 'Stdio' Transport 지원 범위

Legacy는 브라우저 환경이라 Stdio 지원이 제한적이었으나, Rust는 Native Stdio를 완벽 지원합니다. `createServer`에서 Stdio 설정을 받을 때, 보안(Command Allowlist) 검사를 어떻게 적용할지 정책이 필요합니다.

> 답변: 보안에 대한 검사는 하지 말자. 현실적으로 검사할 수 있는 룰기반 방법이 많지 않아. 오히려 제약 사항이 될 수 있어
