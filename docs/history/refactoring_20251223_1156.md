# Refactoring Plan: Rust-Based Agent Runtime (Thronglet)

## 1. 작업의 목적

- **Agentic Workflow의 독립성 확보**: 현재 Frontend에 종속된 Agent 로직을 Backend(Rust)로 이관하여, UI 세션 전환이나 새로고침 시에도 Agent가 중단되지 않고 지속 실행되도록 함.
- **구조적 분리 및 재사용성**: 핵심 Agent 로직을 별도의 독립 라이브러리(`thronglet`)로 분리하여 테스트 용이성을 높이고 향후 다른 인터페이스(CLI 등)로의 확장을 대비함.
- **성능 및 안정성**: Rust의 안정성과 Concurrency 모델을 활용하여 복잡한 Agent Loop를 견고하게 처리.

## 2. 현재의 상태 / 문제점

- **Frontend 종속**: `src/hooks/use-ai-service.ts` 및 `src/hooks/use-tool-processor.ts`에서 Agent의 "Think -> Act -> Observe" 루프를 수행함.
- **세션 중단**: 사용자가 페이지를 이동하거나 브라우저를 새로고침하면 React Component Unmount로 인해 Agent Loop가 강제 종료됨.
- **복잡한 상태 관리**: 비동기 Tool 실행 대기, LLM 스트리밍 처리 등이 React State와 얽혀 디버깅이 어렵고 데드락(UI Freeze) 위험이 있음.

## 3. 관련 코드의 구조 및 동작 방식 Summary (Bird's-eye View)

- **`MCPServerManager`** (`src-tauri/src/mcp/server`): MCP 서버 연결 및 Tool 실행을 담당하는 핵심 컴포넌트. 이미 Built-in 및 External Process 관리가 구현되어 있음.
- **`chat.ts`** (`src/models/chat.ts`): 메시지, 세션, Tool Call에 대한 데이터 모델 정의.
- **`use-ai-service.ts`**: Frontend에서 LLM API 호출 및 응답 스트리밍을 제어하는 Hook.

## 4. 변경 이후의 상태 / 해결 판정 기준

### Architecture: Thronglet & LibrAgent

- **`src-tauri/thronglet`**: Tauri에 의존성이 없는 순수 Rust Agent Runtime 라이브러리.
- **`src-tauri/src/services/agent_server.rs`**: Tauri Command/Event와 Thronglet을 연결하는 Glue Layer.

### 핵심 기능

- **RPC Control**: `agent_start`, `agent_input` 등의 Tauri Command로 Agent 제어.
- **Delegated LLM**: Agent는 직접 LLM API를 호출하지 않고, Frontend(RPC Peer)에게 `llm_request`를 보냄. (API Key 관리 및 모델 설정은 Frontend가 담당)
- **Unified Tooling**: `MCPServerManager`를 감싸서 `thronglet::ToolProvider`를 구현, 내/외부 툴을 투명하게 실행.
- **Mocking Support**: `MockLLMProvider`, `MockToolProvider`를 통해 UI 없이 로직 검증 가능.

### 해결 판정 기준 (Definition of Done)

1.  **Recursive Mechanism Verification**: `cargo test`를 통해 Mock 환경에서 "LLM 응답에 Tool Call이 포함되면 실행 후 다시 LLM을 호출하고, 텍스트만 있으면 종료하는" 재귀 로직이 정상 동작하는지 검증. (특정 Business Flow 검증 아님)
2.  **Persistence**: UI 새로고침 후에도 Agent가 백그라운드에서 작업을 계속 수행하고, 재연결 시 상태가 동기화되어야 함.
3.  **Model Agnostic**: Agent 시작 시 특정 모델을 강제하지 않고, Frontend 설정에 따름.

### B. Core Traits (`thronglet/src/traits.rs`)

```rust
#[async_trait]
pub trait LLMProvider: Send + Sync {
    /// Request text generation from the LLM.
    /// The `config` is opaque to Thronglet (passed through from agent_start).
    async fn generate(&self, history: Vec<Message>, system_prompt: String) -> Result<LLMResponse, AgentError>;
}

#[async_trait]
pub trait ToolProvider: Send + Sync {
    /// Execute a tool by name (unified routing internally).
    async fn call_tool(&self, server_name: &str, tool_name: &str, args: Value) -> Result<ToolResult, AgentError>;

    /// List available servers/tools (for discovery).
    async fn list_tools(&self, server_names: Vec<String>) -> Result<Vec<ToolDefinition>, AgentError>;
}
```

### C. Agent Loop (`thronglet/src/agent.rs`)

```rust
pub struct Agent<L, T> {
    llm_provider: Arc<L>,
    tool_provider: Arc<T>,
    state: AgentState,
}

impl<L, T> Agent<L, T>
where L: LLMProvider, T: ToolProvider
{
    pub async fn run_step(&mut self) -> Result<(), AgentError> {
        // Recursive Tool Loop (Replicating use-tool-processor.ts)
        // 1. Prepare Prompt (History + System Prompt)
        // 2. LLM Generate (Delegated to Frontend)
        // 3. Loop:
        //    a. Parse Tool Calls from Response
        //    b. If No Tool Calls -> Break Loop (Return Final Answer)
        //    c. Execute Tools (Delegated to MCPServerManager)
        //    d. Append Tool Results to History
        //    e. Recurse (Go to Step 2 with updated History)
        Ok(())
    }
}
```

```rust
#[async_trait]
impl ToolProvider for WrappedMcpManager {
    async fn call_tool(...) {
        self.inner.call_tool_unified(server, tool, args).await
    }
}

// Tauri Command to start agent
#[tauri::command]
pub async fn agent_start(
    state: State<'_, AgentRuntimeState>,
    config: AgentConfig
) -> Result<String, String> {
    let agent = Thronglet::new(config, ...);
    let id = state.spawn(agent);
    Ok(id)
}
```

```rust
#[tokio::test]
async fn test_agent_completes_task() {
    let mock_llm = MockLLMProvider::new()
        .expect_prompt("Calculate 1+1")
        .return_tool_call("calculator", "add", json!({"a": 1, "b": 1}));

    let mock_tools = MockToolProvider::new()
        .expect_call("calculator", "add")
        .return_result("2");

    let mut agent = Agent::new(mock_llm, mock_tools);
    agent.input("Calculate 1+1").await;

    assert_eq!(agent.last_response(), "The answer is 2");
}
```
