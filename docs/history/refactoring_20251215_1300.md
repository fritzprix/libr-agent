# Refactoring Plan: Planning Validation & Tool Naming Standardization

## 1. 작업의 목적

- **Planning System 안정성 강화**: Goal 및 Todo 관리 시스템에 입력값 검증 로직을 추가하여, 빈 데이터나 잘못된 의존성으로 인한 시스템 오류 및 데이터 무결성 문제를 방지함.
- **에러 피드백 강화**: 명확한 에러 메시지를 제공하여 AI 모델이 잘못된 요청을 스스로 수정할 수 있도록 유도함.
- **도구 명명 규칙 표준화**: 모든 MCP 도구(`builtin`, `modules`)의 이름과 파라미터를 JSON 표준인 `camelCase`로 통일하여 일관성을 확보함.

## 2. 현재의 상태 / 문제점

### Validation 부재

- **Empty Name**: Goal이나 Todo 생성 시 이름(`name`)이 비어있거나 공백만 있는 경우에도 생성이 허용됨. 이는 UI에서 보이지 않는 항목을 만들거나 혼란을 야기할 수 있음.
- **Invalid Dependency**: Todo 생성 또는 수정 시 `dependsOn` 필드에 존재하지 않는 Todo ID를 입력해도 시스템이 이를 수락함. 이는 추후 의존성 그래프 순회나 실행 순서 결정 시 런타임 에러를 유발할 수 있음.

### Naming Inconsistency

- **Mixed Cases**: 도구 이름과 파라미터가 `snake_case`(예: `read_file`, `file_path`)와 `camelCase`(예: `createGoal`)로 혼용되어 있어 모델의 혼란을 초래하고 JSON 표준을 따르지 않음.
- **Target Modules**:
  - `src/lib/web-mcp/modules`: TypeScript 기반 도구들.
  - `src-tauri/src/mcp/builtin`: Rust 기반 도구들.

## 3. 관련 코드의 구조 및 동작 방식 Summary (Bird's Eye View)

- **Planning Server** (`src/lib/web-mcp/modules/planning-server/`)
  - `managers/goal-manager.ts`: 목표(Goal)의 생성, 조회, 상태 관리를 담당.
  - `managers/todo-manager.ts`: 할 일(Todo)의 생성, 의존성 관리, 상태 변경을 담당.
  - `types.ts`: Goal, Todo 등의 데이터 인터페이스 정의.
- **MCP Tools Definition**
  - **Web MCP**: `src/lib/web-mcp/modules/*/tools.ts` 파일들에 각 모듈별 도구가 정의됨.
  - **Builtin MCP**: `src-tauri/src/mcp/builtin/**/tools/*.rs` 파일들에 Rust 기반 도구가 정의됨.

## 4. 변경 이후의 상태 / 해결 판정 기준

### Goal Validation

- **이름 검증**: `createGoal` 호출 시 `name`이 비어있거나 공백 문자열인 경우 `Error("Goal name cannot be empty")`를 발생시킴.

### Todo Validation

- **이름 검증**: `createTodo` 호출 시 `name`이 비어있거나 공백 문자열인 경우 `Error("Todo name cannot be empty")`를 발생시킴.
- **의존성 검증**: `createTodo` 호출 시 `dependsOn` 배열에 포함된 모든 ID가 현재 존재하는 Todo의 ID인지 확인. 존재하지 않는 ID가 발견되면 `Error("Dependency Todo ID {id} does not exist")`를 발생시킴.

### Tool Naming Standardization

- **Rule**: 모든 도구 이름과 파라미터 키는 `camelCase`를 따른다.
- **Examples**:
  - `read_file` -> `readFile`
  - `file_path` -> `filePath`
  - `list_directory` -> `listDirectory`
- **Scope**: `src/lib/web-mcp/modules` 및 `src-tauri/src/mcp/builtin` 내의 모든 도구 정의.

#### 2. `todo-manager.ts`

```typescript
// createTodo 메서드 내부
public createTodo(input: CreateTodoInput): Todo {
  // Name Validation
  if (!input.name || input.name.trim() === '') {
    throw new Error('Todo name cannot be empty');
  }

  // Dependency Validation
  if (input.dependsOn && input.dependsOn.length > 0) {
    for (const depId of input.dependsOn) {
      if (!this.todoMap.has(depId)) {
        throw new Error(`Dependency Todo ID ${depId} does not exist`);
      }
    }
  }

  // ... existing logic ...
}
```

## 7. Test Code 추가 및 수정 필요 부분

- **Goal Manager Test**:
  - `createGoal`에 빈 이름("") 전달 시 에러가 발생하는지 테스트.
  - 공백 이름(" ") 전달 시 에러가 발생하는지 테스트.
- **Todo Manager Test**:
  - `createTodo`에 빈 이름 전달 시 에러 발생 테스트.
  - `createTodo`에 존재하지 않는 ID(예: 9999)를 `dependsOn`으로 전달 시 에러 발생 테스트.
  - 유효한 ID를 `dependsOn`으로 전달 시 정상 생성되는지 테스트.
- **Tool Naming Test**:
  - 변경된 도구 이름(`camelCase`)으로 호출 시 정상 동작하는지 확인.
  - 기존 테스트 코드에서 구형 이름(`snake_case`)을 사용하는 부분이 있다면 모두 신규 이름으로 업데이트.
