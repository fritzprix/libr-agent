# Shell Isolation Level Configuration Refactoring Plan

## 작업의 목적

사용자가 셸 명령 실행 시 isolation level(격리 수준)을 설정할 수 있도록 하여, 보안성과 사용성 간의 균형을 선택할 수 있도록 개선합니다.

**배경:**

- 현재 모든 셸 도구가 `IsolationLevel::Medium`으로 하드코딩되어 있음
- Medium isolation은 Unix에서 환경 변수를 제거하고 제한된 PATH를 설정함
- 이로 인해 사용자 설치 도구 (`uv`, `pipx` 등)가 실행 실패하는 문제 발생
- 사용자가 보안 수준과 PATH 접근성 사이에서 선택할 수 없음

```rust

// Basic: 환경 변수 및 작업 디렉토리만 설정
// - Windows: 환경 변수 보존
// - Unix: 환경 변수 보존

// Medium: 프로세스 그룹 + 제한된 PATH
// - Windows: CREATE_NEW_PROCESS_GROUP
// - Unix: env_clear() + /bin:/usr/bin:/usr/local/bin + 프로세스 그룹

// High: 플랫폼별 샌드박싱
// - Linux: unshare (user namespaces)
// - macOS: sandbox-exec
// - Windows: Low integrity level
```

### 3. Backend Settings Accessor

**파일:** `src-tauri/src/mcp/builtin/workspace/utils.rs` (신규 함수)

```rust
use crate::state::get_settings_repository;
use crate::session_isolation::IsolationLevel;

/// Get configured shell isolation level from settings
pub async fn get_shell_isolation_level() -> IsolationLevel {
    let repo = get_settings_repository();

    // Try to get isolation level from settings
    match repo.get("system.shellIsolationLevel").await {
        Ok(Some(setting)) => {
            let value: String = serde_json::from_str(&setting.value)
                .unwrap_or_else(|_| "medium".to_string());

            match value.as_str() {
                "basic" => IsolationLevel::Basic,
                "medium" => IsolationLevel::Medium,
                "high" => IsolationLevel::High,
                _ => IsolationLevel::Medium, // Default fallback
            }
        }
        _ => IsolationLevel::Medium, // Default if not set
    }
}
```

## Clarification Q-list

### 1. 기본값 선택: Basic vs Medium vs High

**Q:** Shell isolation level의 기본값을 어떻게 설정할까요?

**각 단계별 상세 설명:**

#### **Basic (가장 낮은 보안 수준)**

```
특징:
├─ 환경변수: 보존 (사용자 홈, PATH, USER 등)
├─ PATH 접근: ✅ 전체 시스템 PATH + ~/.local/bin + ~/.cargo/bin
├─ 사용자 도구: ✅ uv, pipx, cargo-installed tools 모두 실행 가능
├─ 프로세스 격리: ❌ 없음 (일반 자식 프로세스)
└─ 워크스페이스 제한: ❌ 현재 디렉토리만 HOME으로 설정
```

**함의 (Implications):**

- ✅ 사용자 경험 최적 (모든 도구 접근 가능)
- ✅ 기존 스크립트/도구 호환성 최고
- ❌ **⚠️ 악성 코드 실행 위험**: 셸 명령이 전체 시스템 접근 가능
- ❌ **⚠️ 프로세스 탈출**: `fork()` 또는 `exec()` 없음

**사용 시나리오:**

```
✅ 신뢰할 수 있는 도구 실행
✅ 개발 환경 설정
✅ 자신의 시스템에서만 사용
❌ 불신뢰 소스의 명령 실행 금지
❌ 멀티 테넌트 환경
❌ 보안이 중요한 작업
```

---

#### **Medium (균형잡힌 보안)**

```
특징:
├─ 환경변수: 제거 후 필수만 재설정
├─ PATH 접근: 🔒 /bin:/usr/bin:/usr/local/bin + 부분 사용자 경로
├─ 사용자 도구: 🟡 ~/.local/bin, ~/.cargo/bin만 가능
├─ 프로세스 격리: ✅ 프로세스 그룹 생성 (신호 전파 제어)
└─ 워크스페이스 제한: ✅ HOME을 워크스페이스로 제한
```

**함의 (Implications):**

- ✅ 합리적인 보안 수준
- ✅ 대부분의 일반 도구 접근 가능
- ✅ 표준 설치 경로(pip, cargo) 지원
- 🟡 비표준 경로 도구는 실행 불가능
- 🟡 환경변수 의존 도구는 주의 필요

**사용 시나리오:**

```
✅ 권장 기본값
✅ 일반적인 셸 명령 실행
✅ 대부분의 개발 도구
🟡 커스텀 경로 설정 도구는 Basic으로 변경 필요
```

---

#### **High (최고 보안)**

```
특징:
├─ 환경변수: 제거 후 최소한만 설정
├─ PATH 접근: 🔒🔒 /bin:/usr/bin만 (기본 시스템 도구만)
├─ 사용자 도구: ❌ 사용자 설치 도구 실행 불가
├─ 프로세스 격리: ✅✅ 플랫폼별 샌드박싱
│   ├─ Linux: unshare (user namespace)
│   ├─ macOS: sandbox-exec (System Integrity Protection)
│   └─ Windows: Low integrity level
└─ 워크스페이스 제한: ✅✅ 엄격한 경로 제한
```

**함의 (Implications):**

- ✅ **최고 보안**: 악성 코드 실행 거의 불가능
- ✅ **완전 격리**: 프로세스 탈출 불가능
- ❌ **사용성 저하**: 사용자 도구 실행 불가
- ❌ **복잡성**: 플랫폼별 다른 동작
- ❌ **성능**: 샌드박싱 오버헤드

**사용 시나리오:**

```
✅ 신뢰할 수 없는 코드 실행
✅ 멀티 테넌트 환경
✅ 서버/클라우드 배포
✅ 보안 감사 필요 환경
❌ 일반 개발 환경
❌ 사용자 도구가 필요한 작업
```

| 추천 환경   | 개인/신뢰      | **일반적** | 프로덕션       |

### **⚠️ 기본값 선택 권장사항**

**옵션 A) Basic 기본값 (사용성 우선)**

```
장점:
✅ 사용자 불만 최소화
✅ 모든 도구 즉시 작동
✅ 기존 스크립트 호환

위험:
❌ 보안 의식 낮은 사용자는 계속 Basic 사용
❌ 첫 사용자가 악성 명령 실행할 가능성 높음
❌ "AI가 안전하다고 생각" → 실제로는 위험
```

**옵션 B) Medium 기본값 (균형 우선) ✅ 추천**

```
장점:
✅ 합리적인 보안 수준 유지
✅ 일반 도구는 대부분 작동
✅ 문제 발생 시 사용자가 의도적으로 Basic 선택
✅ 보안과 사용성의 최적 균형

단점:
🟡 첫 사용 시 일부 도구 실패 가능
   → 설명 & 가이드 필요
```

**옵션 C) High 기본값 (보안 우선)**

```
장점:
✅ 최고 수준의 보안

단점:
```
