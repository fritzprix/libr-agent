# Refactoring Plan: Type Safety Improvements for `unknown` Anti-Patterns

## 작업의 목적 (Purpose)

Improve type safety across the codebase by eliminating improper uses of `unknown` type and double type assertions. This refactoring aims to:

1. Remove unnecessary double type assertions (`as unknown as Type`)
2. Add proper type guards where `unknown` types are accessed without validation
3. Define explicit interfaces for external API responses and dynamic data structures
4. Improve maintainability and catch potential runtime errors at compile-time

## 현재의 상태 / 문제점 (Current State / Problems)

### Overall Assessment

The codebase successfully avoids `any` type usage, adhering to strict TypeScript practices. However, there are several instances where `unknown` is used inappropriately:

### Problem Categories

#### 1. Unnecessary Double Type Assertions

- **Location**: `src/context/LLMServiceContext.tsx:365`
- **Issue**: `provider as unknown as AIServiceProvider`
  - Double casting when single cast would suffice
  - `provider` parameter is already a string matching enum values
  - Adds unnecessary complexity

#### 2. Unsafe Property Access on Unknown Types

- **Location**: `src/lib/tool-call-utils.ts:15`
- **Issue**: `(c as Record<string, unknown>).isError === true`
  - Accesses `isError` property not defined in `MCPContent` union type
  - No type guard validation before property access
  - Could cause runtime errors if structure changes

#### 3. Unvalidated JSON Parsing

- **Location**: `src/lib/tool-call-utils.ts:52`
- **Issue**: `JSON.parse(argumentsString) as Record<string, unknown>`
  - Assumes parsed JSON is always an object
  - No structure validation after parsing
  - Wrapped in try-catch but returns unsafe cast

#### 4. Environment-Specific Timer Type Mismatches

- **Location**: `src/features/settings/SettingsPage.tsx:80`
- **Issue**: `window.setTimeout(...) as unknown as number`
  - `setTimeout` returns different types in browser vs Node.js
  - Double assertion masks the actual type mismatch
  - Should use proper union typing

#### 5. Nullable Static Property Workarounds

- **Location**: `src/lib/db/database.ts:38`
- **Issue**: `LocalDatabase.instance = null as unknown as LocalDatabase`
  - Static property typed as non-nullable but assigned null
  - Uses type assertion to bypass compiler checks
  - Should be typed as `LocalDatabase | null`

#### 6. External API Response Handling

- **Location**: `src/scripts/test_ollama_reasoning_chunks.ts:40`
- **Issue**: `(chunk.message as unknown as Record<string, unknown>)`
  - Double casting for Ollama API responses
  - No explicit interface for expected structure
  - Makes code harder to understand and maintain

### Change 2: Add Type Guard for Content Error Checking

**File**: `src/lib/tool-call-utils.ts:15`

**Before**:

```typescript
if (
  toolResult?.content?.some(
    (c) => (c as Record<string, unknown>).isError === true,
  )
) {
  return true;
}
```

**After**:

```typescript
// Add interface extension
interface MCPErrorContent extends MCPTextContent {
  isError: boolean;
}

// Add type guard
function isErrorContent(content: MCPContent): content is MCPErrorContent {
  return (
    content.type === 'text' &&
    'isError' in content &&
    (content as { isError?: boolean }).isError === true
  );
}

// Update function
if (toolResult?.content?.some(isErrorContent)) {
  return true;
}
```

**Rationale**: Provides type-safe way to check for error content without unsafe assertions.

### Change 4: Fix Database Singleton Nullable Type

**File**: `src/lib/db/database.ts:18-38`

**Before**:

```typescript
export class LocalDatabase extends Dexie {
  private static instance: LocalDatabase;

  // ...

  public static resetInstance(): void {
    if (LocalDatabase.instance) {
      LocalDatabase.instance.close();
      LocalDatabase.instance = null as unknown as LocalDatabase;
    }
  }
}
```

**After**:

```typescript
export class LocalDatabase extends Dexie {
  private static instance: LocalDatabase | null = null;

  public static getInstance(): LocalDatabase {
    if (!LocalDatabase.instance) {
      LocalDatabase.instance = new LocalDatabase();
    }
    return LocalDatabase.instance;
  }

  public static resetInstance(): void {
    if (LocalDatabase.instance) {
      LocalDatabase.instance.close();
      LocalDatabase.instance = null;
    }
  }
}
```

**Rationale**: Properly declares nullable type, eliminating need for unsafe assertion.

### Change 5: Define Ollama API Response Interface

**File**: `src/scripts/test_ollama_reasoning_chunks.ts:40`

**Before**:

```typescript
const message =
  hasMessage && chunk.message && typeof chunk.message === 'object'
    ? (chunk.message as unknown as Record<string, unknown>)
    : null;
```

**After**:

```typescript
// Add interface at top of file
interface OllamaChunkMessage {
  content?: string;
  thinking?: string;
  role?: string;
}

interface OllamaStreamChunk {
  message?: OllamaChunkMessage;
  done?: boolean;
  [key: string]: unknown;
}

// Update code
function isOllamaStreamChunk(obj: unknown): obj is OllamaStreamChunk {
  return (
    typeof obj === 'object' &&
    obj !== null &&
    (!('message' in obj) || typeof obj.message === 'object')
  );
}

// Usage
if (!isOllamaStreamChunk(chunk)) continue;
const message = chunk.message ?? null;
```

**Rationale**: Explicit interface improves readability and type safety for external API.

### Change 6: Improve JSON Parsing in Tool Arguments (Optional Enhancement)

**File**: `src/lib/tool-call-utils.ts:52`

**Current** (acceptable but could be improved):

```typescript
export function parseToolArguments(
  argumentsString: string,
): Record<string, unknown> {
  try {
    return JSON.parse(argumentsString) as Record<string, unknown>;
  } catch {
    return { raw: argumentsString };
  }
}
```

**Enhanced Option** (if validation needed):

```typescript
function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value);
}

export function parseToolArguments(
  argumentsString: string,
): Record<string, unknown> {
  try {
    const parsed = JSON.parse(argumentsString);
    return isRecord(parsed) ? parsed : { value: parsed };
  } catch {
    return { raw: argumentsString };
  }
}
```

**Note**: This change is optional since current implementation is acceptable for dynamic tool arguments.
