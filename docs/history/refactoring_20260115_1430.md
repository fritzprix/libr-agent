# CMD Support Implementation Refactoring Plan

## 1. 작업의 목적

- Windows 환경에서 **Legacy Command (Batch script 등)** 및 **CMD 고유 문법** 지원을 위해 `cmd.exe` 실행 지원 추가.
- `powershell`과 `cmd`를 명시적으로 구분하여 선택할 수 있는 Tool 제공.
- 현재 PowerShell로 강제되는 실행 환경을 유연하게 확장.

## 2. 현재의 상태 / 문제점

- **Shell Detection**: `detect_shell` 함수는 `cmd`와 `powershell`을 구분하지만, 실제 실행에는 영향을 주지 않음.
- **Execution Hardcoding**:
  - `PersistentShell`은 Windows에서 무조건 `powershell.exe`를 실행함.
  - `SessionIsolationManager`는 Windows에서 기본 Shell로 `powershell`을 반환함.
- **Tools**:
  - Windows용 Tool은 `runPowerShell`, `runInPersistentPowerShell`만 존재.
  - CMD 전용 Tool (`runCmd`, `runInPersistentCmd`) 부재.
  - `execute_windows_cmd` 요청 시 에러를 반환하며 PowerShell 사용을 강제함.

## 3. 관련 코드의 구조 및 동작 방식 Summary (Birdeye View)

### A. Shell Execution Flow

1. **Frontend/Agent**: Calls `runPowerShell` or `runInPersistentPowerShell`.
2. **Workspace Handler**:
   - `handle_run_shell` → `execute_shell_with_isolation` (`code_execution/shell.rs`)
   - `handle_execute_shell` → `PersistentShellManager::get_or_create` (`persistent_shell_manager.rs`)
3. **Core Logic**:
   - `SessionIsolationManager` (`session_isolation.rs`): Wraps commands. Defaults to `powershell`.
   - `PersistentShell` (`persistent_shell.rs`): Spawns the actual long-running shell process. Hardcodes arguments (`-NoProfile`, etc.).

### B. Windows Specifics

- **SessionIsolationManager**:
  - `get_shell_command()` returns `"powershell"`.
  - `create_basic_isolated_command()` detects `powershell` prefix to avoid wrapping, otherwise wraps in default shell (PowerShell).
- **PersistentShell**:
  - Uses `powershell.exe` with `-NonInteractive`.
  - Sets encoding to UTF-8 using PowerShell-specific command `[Console]::OutputEncoding...`.

## 4. 변경 이후의 상태 / 해결 판정 기준

### 변경 후 상태

1. **Shell Type Support**:
   - `PersistentShell` 및 `SessionIsolationManager`가 `ShellType` (PowerShell | Cmd | Bash)을 인지하고 처리.
2. **New Tools**:
   - Windows 환경에서 `runCmd` (Isolated), `runInPersistentCmd` (Persistent) Tool 사용 가능.
3. **Cmd Specific Handling**:
   - `cmd.exe` 실행 시 적절한 argument (`/Q`, `/K` 등) 및 encoding 처리 (`chcp 65001`).

### 해결 판정 기준

- `runCmd` Tool을 통해 `dir`, `echo %CD%` 등의 CMD 명령어 실행 성공.
- `runInPersistentCmd` Tool을 통해 변수 설정 (`set VAR=1`) 후 후속 호출에서 확인 가능.
- 기존 `runPowerShell` 기능에 영향 없음 (Regression Test).

    let mut cmd = match shell_type {
        ShellType::PowerShell => {
            let mut c = Command::new("powershell.exe");
            c.arg("-NoProfile").arg("-NonInteractive");

        ShellType::Cmd => {
            let mut c = Command::new("cmd.exe");
