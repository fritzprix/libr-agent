# Refactoring Plan: Fix Duplicate MCP Tools & Session Isolation Conflict

## 1. 작업 목적 (Purpose)

- **MCP 도구 중복 제거**: 현재 Stdio 기반의 외부 MCP 서버 도구가 AI 에이전트에게 2중으로(Global + Session) 노출되어 발생하는 오류("Duplicate function declaration") 수정.
- **세션 격리 강화**: Stdio 서버는 반드시 세션별로 격리된 프로세스(`SessionMCPManager`)를 통해서만 관리되도록 강제하고, Global Manager가 이에 개입하지 않도록 수정.

## 2. 현재 상태 / 문제점 (Current Status / Problems)

### 2.1 아키텍처 충돌

현재 코드는 Stdio MCP 서버를 두 곳에서 관리하고 있습니다:

1. **Global `MCPServerManager`**: "상태 확인" 기능이나 `list_tools_from_config` 실행 시 Stdio 프로세스를 Global Connection으로 등록함.
2. **Session `SessionMCPManager`**: 세션 생성 시(`create_proxy`) `eager tool discovery`를 통해 세션 전용 프로세스를 생성하고 도구를 등록함.

### 2.2 중복 도구 발생 경로

`src-tauri/src/agent/tools.rs`의 `collect_available_tools` 함수에서 도구를 수집할 때:

1. `proxy_manager.list_all_external_tools()`를 호출하여 Global Manager의 도구를 가져옴 (여기서 Stdio 도구가 1차로 포함됨).
2. `proxy.get_session_stdio_tools()`를 호출하여 Session Manager의 도구를 가져옴 (여기서 Stdio 도구가 2차로 포함됨).
3. 결과적으로 동일한 도구가 2개씩 존재하게 되어 LLM 호출 시 스키마 중복 에러 발생.

## 3. 변경 이후의 상태 (Target State)

- **Global Manager**: HTTP 기반의 공유 MCP 서버만 관리. `list_all_tools` 호출 시 Stdio 서버는 배제함.
- **Session Manager**: Stdio 기반의 격리된 MCP 서버만 관리.
- **Frontend**: "상태 확인" 등으로 인해 Global Manager에 Stdio 연결이 임시로 생기더라도, Agent 도구 수집 단계에서는 무시됨.

## 4. 수정이 필요한 코드 및 구현 가이드 (Implementation Guide)

### 4.1 `src-tauri/src/mcp/server/tools.rs` 수정

Global Manager가 관리하는 연결(`connections`) 중에서 **Stdio 타입은 필터링하고 HTTP 타입만 반환**하도록 `list_all_tools` 함수를 수정합니다.

```rust
// src-tauri/src/mcp/server/tools.rs

use crate::mcp::types::TransportConfig; // Import 추가 필요

pub async fn list_all_tools(manager: &MCPServerManager) -> Result<Vec<MCPTool>> {
    let mut all_tools = Vec::new();

    // Server names 수집 단계에서 TransportConfig::Http 인 것만 필터링
    let server_names: Vec<String> = {
        let connections = manager.connections.lock().await;
        connections.iter()
            .filter(|(_, conn)| {
                // ✅ FIX: Stdio 서버는 Global 리스트에서 제외 (SessionManager가 담당)
                matches!(conn.config.transport, TransportConfig::Http { .. })
            })
            .map(|(name, _)| name.clone())
            .collect()
    };

    for server_name in server_names {
        match list_tools(manager, &server_name).await {
            Ok(mut tools) => {
                // Prefix logic 유지
                for tool in &mut tools {
                    tool.name = format!("{}__{}", server_name, tool.name);
                }
                all_tools.extend(tools);
            }
            Err(e) => {
                warn!("Failed to get tools from server {server_name}: {e}");
            }
        }
    }

    Ok(all_tools)
}
```

### 4.2 `src-tauri/src/commands/mcp_commands.rs` (Optional / Future Work)

현재 `list_tools_from_config`는 설정 검증을 위해 `manager.start_server`를 호출하여 부작용(Global state에 Stdio process 생성)을 일으킵니다.
이번 리팩토링에서는 4.1의 필터링으로 중복 노출을 막는 것을 우선으로 하되, 장기적으로는 이 함수가 Global Manager에 영구적인 연결을 남기지 않도록 `stop_server`를 마지막에 호출하거나 별도의 검증 로직을 사용하는 것이 좋습니다. (이번 계획에서는 4.1 적용만으로 해결 판정 가능)

## 5. 해결 판정 기준 (Acceptance Criteria)

1. **중복 제거 확인**: Agent Session에서 Stdio MCP 서버(예: `rpg-mcp-server`)를 사용할 때, `collect_available_tools` 결과에 해당 도구가 **단 한 번만** 등장해야 함.
2. **기능 유지 확인**:
   - HTTP 기반 MCP 서버는 여전히 Global Manager를 통해 정상적으로 검색되어야 함.
   - Session-isolated Stdio 서버는 Session Manager를 통해 정상적으로 검색되어야 함.
