# Refactoring Plan: LLM Token Usage Metering & UI Display

**작성일**: 2026-01-09  
**담당**: Agent Development Team  
**버전**: 1.0

---

## 1. 작업의 목적

LLM 서비스의 토큰 사용량과 성능 메트릭을 실시간으로 수집하고 사용자에게 시각적으로 표시하는 기능을 추가한다.

**핵심 목표**:

- AI 서비스 사용 비용 투명성 확보 (입력/출력 토큰 수 표시)
- 모델 성능 가시성 확보 (Tokens/sec, 응답 시간 측정)
- 사용자가 실시간으로 진행 상황과 리소스 소비를 확인 가능

---

## 2. 현재의 상태 / 문제점

### 2.1 현재 상태

**AI Service Layer** (`src/lib/ai-service/`):

- 모든 프로바이더 (OpenAI, Anthropic, Gemini, Groq, Ollama 등)가 streaming API를 통해 응답 반환
- 각 프로바이더의 SDK는 토큰 사용량 데이터를 제공하지만, **현재 구현에서는 이를 무시하고 폐기**
- `doStreamChat()` 메서드가 content와 tool_calls만 yield하고 usage 데이터는 추출하지 않음

**Ollama 사례**:

```typescript
// ollama-core.ts - processChunk()
// ❌ 현재: eval_count, prompt_eval_count 등 메트릭 필드를 무시
if (c.done === true) {
  // chunk.eval_count (output tokens)
  // chunk.prompt_eval_count (input tokens)
  // chunk.eval_duration (generation time in ns)
  // → 모두 무시됨
}
```

**LLMServiceContext**:

- `executeCompletionRequest()`가 스트림에서 content/tool_calls만 추출
- 토큰 사용량과 성능 메트릭을 로깅조차 하지 않음

**UI Layer**:

- Agent Chat UI에 토큰 사용량 표시 기능 없음
- 사용자는 현재 얼마나 많은 토큰을 소비했는지 알 수 없음
- 성능 지표 (Tokens/sec) 표시 없음

### 2.2 문제점

1. **비용 관리 불가**: 사용자가 API 호출 비용을 예측하거나 모니터링할 수 없음
2. **성능 가시성 부족**: 모델의 응답 속도를 정량적으로 평가할 수 없음
3. **데이터 손실**: 프로바이더가 제공하는 유용한 메트릭을 버림
4. **디버깅 어려움**: 토큰 제한 초과나 성능 이슈 발생 시 원인 파악 어려움

## 4. 변경 이후의 상태 / 해결 판정 기준

### 4.1 기대 결과

**Service Layer**:

- ✅ 모든 프로바이더가 `usage` 데이터를 JSON chunk로 yield
- ✅ 프로바이더별 차이는 내부적으로 정규화되어 통일된 `TokenUsage` 인터페이스로 제공

**Context Layer**:

- ✅ `LLMServiceContext`가 usage 데이터를 추출하고 메트릭 계산 (Tokens/sec 등)
- ✅ `streamingMessages` Map에 usage 정보 포함

**UI Layer**:

- ✅ AgentChatStatusBar에 메트릭 배지 표시: "📊 127↑ 543↓ • 42.3 t/s"
- ✅ 실시간 업데이트 (streaming 중)
- ✅ 최종 메트릭 표시 (완료 후)

### 4.2 성공 판정 기준

**기능 검증**:

1. Ollama 로컬 모델 호출 시 입력/출력 토큰 수 정확히 표시
2. OpenAI API 호출 시 최종 chunk에서 usage 추출 및 표시
3. Anthropic Claude 호출 시 message_stop에서 usage 추출 및 표시
4. Tokens/sec 계산이 실제 생성 속도와 일치 (±5% 오차)
5. UI에 메트릭이 실시간으로 업데이트됨 (1초 이내 반영)

**성능 요구사항**:

- 메트릭 수집이 응답 속도에 영향 없음 (오버헤드 <10ms)
- UI 렌더링 최적화로 불필요한 리렌더링 방지

**사용성 요구사항**:

- 메트릭이 명확하고 직관적으로 표시됨 (아이콘, 색상 구분)
- 모바일/작은 화면에서도 가독성 유지

```typescript
export interface ProcessedChunk {
  content?: string;
  tool_calls?: unknown[];
  thinking?: string;
  usage?: TokenUsage; // 추가
}

// ✅ processChunk 함수 수정
export function processChunk(
  chunk: unknown,
  logger: Logger = noopLogger,
): ProcessedChunk | null {
  if (!chunk || typeof chunk !== 'object') {
    return null;
  }

  const c = chunk as Record<string, unknown>;
  const result: ProcessedChunk = {};

  // ... 기존 content/tool_calls/thinking 추출 로직 ...

  // ✅ 추가: Usage metrics 추출 (final chunk when done=true)
  if (c.done === true) {
    const promptTokens = Number(c.prompt_eval_count) || 0;
    const completionTokens = Number(c.eval_count) || 0;

    result.usage = {
      promptTokens,
      completionTokens,
      totalTokens: promptTokens + completionTokens,
      details: {
        // Ollama returns nanoseconds, convert to milliseconds
        promptEvalDuration: c.prompt_eval_duration
          ? Number(c.prompt_eval_duration) / 1_000_000
          : undefined,
        evalDuration: c.eval_duration
          ? Number(c.eval_duration) / 1_000_000
          : undefined,
        totalDuration: c.total_duration
          ? Number(c.total_duration) / 1_000_000
          : undefined,
        loadDuration: c.load_duration
          ? Number(c.load_duration) / 1_000_000
          : undefined,
      },
    };

    logger.info('📊 Ollama usage metrics extracted', {
      inputTokens: result.usage.promptTokens,
      outputTokens: result.usage.completionTokens,
      totalTokens: result.usage.totalTokens,
      evalDurationMs: result.usage.details?.evalDuration?.toFixed(2),
    });
  }

  // Return null if no data
  if (
    !result.content &&
    !result.tool_calls &&
    !result.thinking &&
    !result.usage
  ) {
    return null;
  }

  return result;
}
```

```typescript
/**
 * Calculate tokens per second from usage metrics
 */
export function calculateTokensPerSecond(
  usage: TokenUsage,
  durationMs: number,
): number {
  if (usage.completionTokens === 0 || durationMs === 0) return 0;
  return (usage.completionTokens / durationMs) * 1000;
}

/**
 * Format usage metrics for display
 */
export function formatUsageMetrics(usage: TokenUsage): {
  input: string;
  output: string;
  total: string;
  speed?: string;
} {
  return {
    input: usage.promptTokens.toLocaleString(),
    output: usage.completionTokens.toLocaleString(),
    total: usage.totalTokens.toLocaleString(),
    speed: usage.details?.evalDuration
      ? `${((usage.completionTokens / usage.details.evalDuration) * 1000).toFixed(1)} t/s`
      : undefined,
  };
}
```

```typescript
    output: string;
    speed: string | null;
  } | null;
} {
  const { streamingMessages } = useLLMService();

  const metrics = useMemo((): TokenUsage | null => {
    if (!sessionId) return null;
    const message = streamingMessages.get(sessionId);
    return message?.usage ?? null;
  }, [sessionId, streamingMessages]);

  const formattedMetrics = useMemo(() => {
    if (!metrics) return null;

    let speed: string | null = null;
    if (metrics.details?.evalDuration && metrics.completionTokens > 0) {
      const tps =
        (metrics.completionTokens / metrics.details.evalDuration) * 1000;
      speed = tps.toFixed(1);
    }

    return {
      input: metrics.promptTokens.toString(),
      output: metrics.completionTokens.toString(),
      speed,
    };
  }, [metrics]);

  return { metrics, formattedMetrics };
}
```
