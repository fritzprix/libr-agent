# Refactoring Plan: Playbook Schema Enhancement for Template-Based Reusability

## 작업의 목적

현재 Playbook 스키마는 "특정 실행 기록"을 저장하는데는 적합하지만, **"재사용 가능한 워크플로우 템플릿"**으로 활용하기에는 범용성이 부족합니다. 이 리팩토링은 Playbook이 입력 변수(inputs)를 통해 매개변수화되어, 동일한 워크플로우를 다양한 맥락에서 재사용할 수 있도록 개선하는 것을 목표로 합니다.

### 핵심 개선 사항

1. **입력 변수 정의 추가**: Playbook에 `inputs` 필드를 추가하여 실행 시 주입될 매개변수를 명시
2. **템플릿 문자열 지원**: `description`, `purpose` 등에서 `{{variableName}}` 형태의 변수 참조 지원
3. **범용 플레이북 활성화**: 단일 플레이북을 다양한 입력으로 재실행 가능하게 하여 Agent의 생산성 향상

## 현재의 상태 / 문제점

### 현재 스키마 구조 (`src/types/playbook.ts`)

```typescript
export interface Playbook {
  agentId: string;
  goal: string;
  initialCommand: string; // 특정 실행에 종속된 명령
  workflow: PlaybookStep[];
  successCriteria: {
    description: string;
    requiredArtifacts?: string[];
  };
}

export interface PlaybookStep {
  stepId: string;
  description: string; // 하드코딩된 텍스트
  action: {
    toolName: string;
    purpose: string; // 하드코딩된 목적
  };
  requiredData: string[];
  outputVariable: string;
}
```

### 주요 문제점

1. **입력 변수 부재**
   - `initialCommand`는 특정 실행의 자연어 명령("애플의 주가 분석해줘")을 그대로 저장
   - 동일한 로직을 다른 대상("삼성전자")에 적용하려면 새 플레이북을 생성하거나 전체 수정 필요

2. **하드코딩된 값**
   - `description`: "애플의 재무제표 검색"과 같이 구체적 값이 박혀있음
   - `purpose`: "Search for Apple's latest financial report"처럼 특정 기업명이 고정됨

3. **재사용성 제한**
   - 플레이북이 "실행 기록" 역할은 하지만, "템플릿"으로 활용 불가
   - Agent가 유사한 작업을 반복할 때마다 새로운 플레이북 생성 필요

## 재사용 가능한 연관 코드

### 템플릿 치환 유틸리티 (향후 구현 대비)

템플릿 문자열 치환 로직은 현재 단계에서는 추가하지 않지만, 다음과 같은 구조로 준비할 수 있습니다.

**파일 위치:** `src/lib/web-mcp/modules/playbook-store/template-utils.ts` (신규)

```typescript
import type { Playbook, PlaybookInput } from '@/types/playbook';

/**
 * Substitutes {{variableName}} placeholders with actual values
 * @param template - Template string with {{variable}} placeholders
 * @param inputs - Input definitions from playbook
 * @param values - Actual values for substitution
 * @returns Resolved string with substituted values
 */
export function substituteTemplate(
  template: string,
  inputs: PlaybookInput[],
  values: Record<string, string | number | boolean>,
): string {
  let result = template;

  for (const input of inputs) {
    const value = values[input.name] ?? input.defaultValue ?? '';
    const placeholder = new RegExp(`\\{\\{${input.name}\\}\\}`, 'g');
    result = result.replace(placeholder, String(value));
  }

  return result;
}

/**
 * Validates that all required inputs have values
 */
export function validateInputs(
  inputs: PlaybookInput[],
  values: Record<string, unknown>,
): { valid: boolean; missing: string[] } {
  const missing = inputs
    .filter((inp) => !inp.defaultValue && !(inp.name in values))
    .map((inp) => inp.name);

  return {
    valid: missing.length === 0,
    missing,
  };
}

/**
 * Resolves a playbook by substituting all template strings
 */
export function resolvePlaybook(
  playbook: Playbook,
  inputValues: Record<string, string | number | boolean>,
): Playbook {
  const { valid, missing } = validateInputs(playbook.inputs, inputValues);
  if (!valid) {
    throw new Error(`Missing required inputs: ${missing.join(', ')}`);
  }

  return {
    ...playbook,
    goal: substituteTemplate(playbook.goal, playbook.inputs, inputValues),
    workflow: playbook.workflow.map((step) => ({
      ...step,
      description: substituteTemplate(
        step.description,
        playbook.inputs,
        inputValues,
      ),
      action: {
        ...step.action,
        purpose: substituteTemplate(
          step.action.purpose,
          playbook.inputs,
          inputValues,
        ),
      },
    })),
    successCriteria: {
      ...playbook.successCriteria,
      description: substituteTemplate(
        playbook.successCriteria.description,
        playbook.inputs,
        inputValues,
      ),
      requiredArtifacts: playbook.successCriteria.requiredArtifacts?.map(
        (artifact) =>
          substituteTemplate(artifact, playbook.inputs, inputValues),
      ),
    },
  };
}
```

### 3. Handlebars 템플릿 치환 테스트 (기존 재사용)

**파일 위치:** `src/lib/web-mcp/utils/__tests__/ui-utils.test.ts` (기존)

기존 `renderTemplate` 테스트를 참고하여 플레이북 템플릿 패턴 테스트 추가:

```typescript
import { describe, it, expect } from 'vitest';
import { renderTemplate } from '../ui-utils';

describe('renderTemplate - Playbook Use Cases', () => {
  it('should substitute playbook input variables', () => {
    const template = 'Analyze {{targetCompany}} financial report for {{year}}';
    const result = renderTemplate(template, {
      targetCompany: 'Apple',
      year: 2024,
    });
    expect(result).toBe('Analyze Apple financial report for 2024');
  });

  it('should handle conditionals for workflow steps', () => {
    const template =
      '{{#if includeCompetitors}}Compare with competitors{{else}}Solo analysis{{/if}}';
    const result1 = renderTemplate(template, { includeCompetitors: true });
    const result2 = renderTemplate(template, { includeCompetitors: false });
    expect(result1).toBe('Compare with competitors');
    expect(result2).toBe('Solo analysis');
  });

  it('should handle loops for multiple targets', () => {
    const template = '{{#each companies}}{{this}} {{/each}}';
    const result = renderTemplate(template, {
      companies: ['Apple', 'Google', 'Microsoft'],
    });
    expect(result).toBe('Apple Google Microsoft ');
  });

  it('should use default values from Handlebars context', () => {
    const template = 'Year: {{year}}';
    const result = renderTemplate(template, { year: 2024 });
    expect(result).toBe('Year: 2024');
  });
});
```

## Clarification Q-List & Decisions

### ✅ Q1: `agentId` 필수 여부 결정

**결정:** A. `agentId` 필수 유지 (현재 동작)

**이유:**

- Playbook은 Agent의 능력(도구, 시스템 프롬프트)에 종속되어 있음
- Agent별로 사용 가능한 도구가 다르므로, 플레이북은 특정 Agent 컨텍스트에서만 유효
- Agent 종속성을 명확히 하여 실행 시 혼란 방지

**구현 방침:**

- `agentId` 필수 필드 유지
- `currentAssistantId`가 없으면 에러 반환 (현재 동작 유지)
- 플레이북 생성/실행은 항상 특정 Agent 컨텍스트 내에서만 가능

### ✅ Q2: 템플릿 문법 확장 범위

**결정:** B. Handlebars 전체 문법 지원

**이유:**

- Handlebars는 널리 알려진 업계 표준 템플릿 엔진
- 프로젝트에서 이미 UI 렌더링에 Handlebars 사용 중 (`src/lib/web-mcp/utils/ui-utils.ts`)
- 조건문, 반복문 등 고급 문법 지원으로 복잡한 워크플로우 표현 가능

**구현 방침:**

- 기존 `renderTemplate` 유틸리티 재사용
- `{{variableName}}` 단순 변수 치환
- `{{#if condition}}...{{/if}}` 조건문 지원
- `{{#each array}}...{{/each}}` 반복문 지원
- Handlebars 내장 헬퍼 활용 가능

### ✅ Q3: 입력 변수 타입 검증

**결정:** B. 타입 힌트만 제공 (Agent가 자율적으로 판단)

**이유:**

- Playbook 실행은 AI Agent가 도구를 활용하는 복잡한 과정
- Agent가 자연어로 입력값을 추론하고 변환할 수 있음
- 엄격한 타입 검증은 Agent의 유연성을 제한할 수 있음

**구현 방침:**

- `type` 필드는 문서화 및 가이드 목적으로만 사용
- Agent에게 입력 변수의 의도된 타입을 힌트로 제공
- 실행 시 타입 검증은 수행하지 않음
- Agent가 프롬프트에서 타입 정보를 참고하여 적절한 값 선택

### ✅ Q4: IndexedDB 버전 업그레이드 필요성

**결정:** A. DB 버전 업그레이드 수행 (하위 호환성 불필요)

**이유:**

- 사용자가 명시적으로 하위 호환성 불필요 명시
- 새 인덱스 추가로 플레이북 검색 성능 향상
- 깨끗한 스키마로 재시작 가능

**구현 방침:**

- IndexedDB 버전을 2로 업그레이드
- `playbooks` 테이블에 `title` 인덱스 추가
- 기존 데이터 마이그레이션 불필요 (DB 리셋)
- 업그레이드 시 모든 플레이북 데이터 삭제 안내
