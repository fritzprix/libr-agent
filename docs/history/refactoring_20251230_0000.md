# Refactoring Plan: Aligning Rust v2 Tools with Legacy v1 Schemas

## 1. 작업의 목적

Rust 기반의 v2 Built-in Tool들이 Legacy TypeScript (v1) 구현체와 완전히 호환되도록 스키마와 내부 로직을 조정합니다. 이를 통해 기존 프롬프트나 클라이언트 코드가 수정 없이 v2로 마이그레이션될 수 있도록 보장하고, v1에서 제공하던 고급 검색 기능이나 에러 가이드를 v2에도 이식하여 기능 퇴행(Regression)을 방지합니다.

## 2. 현재의 상태 / 문제점

최근 수행한 [Legacy vs Rust Tools Evaluation](../architecture/legacy-vs-rust-tools-evaluation.md) 결과, 다음과 같은 불일치가 확인되었습니다.

1.  **Assistant Management**:
    - `listAssistants`: v1은 `page`/`pageSize`를 사용하나, v2는 `limit`/`offset`을 사용함.
    - `createAssistant`: v1은 `mcpServerIds` 등의 필드명을 사용하나, v2는 `mcpServers` 등을 사용하며 일부 필드 구성이 다름.
2.  **Content Store**:
    - Tool 이름 불일치: v1 `searchKnowledge` vs v2 `keywordSimilaritySearch`.
    - Tool 이름 불일치: v1 `saveKnowledge` vs v2 `addContent`.
    - 스키마 불일치: v1은 `tags`를 명시적으로 지원했으나 v2는 메타데이터로 처리하거나 검색 시 태그 필터링이 명확하지 않음.
3.  **MCP Manager**:
    - `searchServer`: v1은 `searchMode` (BM25/Simple), `weights` 등 고급 옵션을 지원했으나 v2는 단순 `query`만 지원함.
4.  **Browser Tools**:
    - 에러 핸들링: v1의 친절한 에러 가이드(Error Guidance)가 v2에는 일부만 적용되어 있거나 Raw Error를 반환함.

## 3. 관련 코드의 구조 및 동작 방식 Summary

### Legacy (v1)

- **Browser**: `src/features/tools/browser-tools/` (특히 `error-utils.ts`)
- **Assistant**: `src/lib/web-mcp/modules/assistant-manager/tools.ts`
- **Content**: `src/lib/web-mcp/modules/knowledge-server/tools.ts`
- **MCP Manager**: `src/lib/web-mcp/modules/mcp-manager/tools.ts`

### Rust (v2)

- **Browser**: `src-tauri/src/mcp/builtin/browser.rs`
  - `BrowserServer` 구조체 내 `call_tool`에서 도구 실행 분기.
- **Assistant**: `src-tauri/src/mcp/builtin/assistant/mod.rs`
  - `create_list_assistants_tool` 등에서 스키마 정의.
- **Content Store**: `src-tauri/src/mcp/builtin/content_store/`
  - `mod.rs`에서 라우팅, `schemas.rs`에서 스키마 정의.
- **MCP Manager**: `src-tauri/src/mcp/builtin/mcp_manager/mod.rs`

## 4. 변경 이후의 상태 / 해결 판정 기준

1.  **Schema Parity**: 모든 v2 툴의 `inputSchema`가 v1과 호환되어야 함 (필드명, 타입).
2.  **Name Parity**: v1에서 사용하던 툴 이름을 그대로 사용할 수 있어야 함 (Alias 처리 또는 이름 변경).
3.  **Functional Parity**: `searchServer`의 검색 옵션 등 v1의 기능이 v2에서도 동작해야 함.
4.  **Error Handling**: 브라우저 관련 에러 발생 시 v1 수준의 가이드 메시지가 포함되어야 함.

## 5. 수정이 필요한 코드 및 수정부분의 코드 스니핏

### A. Assistant Server (`src-tauri/src/mcp/builtin/assistant/mod.rs`)

- **`listAssistants`**: `limit`/`offset` 대신 `page`/`pageSize` 파라미터 수용 및 내부 변환 로직 추가.
- **`createAssistant`**: `mcpServers` -> `mcpServerIds`로 필드명 변경 또는 둘 다 지원.

```rust
// listAssistants 스키마 수정 예시
props.insert("page".to_string(), integer_prop(Some(1), None, Some("Page number")));
props.insert("pageSize".to_string(), integer_prop(Some(20), None, Some("Items per page")));
// 내부 로직에서 limit = pageSize, offset = (page - 1) * pageSize 로 변환
```

### B. Content Store (`src-tauri/src/mcp/builtin/content_store/`)

- **Tool Renaming/Aliasing**:
  - `keywordSimilaritySearch` -> `searchKnowledge` (또는 Alias 추가)
  - `addContent` -> `saveKnowledge` (또는 Alias 추가)
- **Schema Adaptation**:
  - `saveKnowledge` 호출 시 `tags` 파라미터를 받아 내부적으로 `metadata`에 저장하도록 매핑.

```rust
// mod.rs call_tool 매칭 수정
match tool_name {
    "addContent" | "saveKnowledge" => self.handle_add_content(args).await,
    "keywordSimilaritySearch" | "searchKnowledge" => self.handle_keyword_search(args).await,
    // ...
}
```

### C. MCP Manager (`src-tauri/src/mcp/builtin/mcp_manager/mod.rs`)

- **`searchServer`**: Legacy 스키마(`searchMode`, `weights` 등)를 수용하도록 `input_schema` 확장.
- **Logic**: Rust 내 검색 로직에서 해당 파라미터를 무시하지 않고(가능하다면) 구현하거나, 최소한 에러가 나지 않도록 처리.

### D. Browser Server (`src-tauri/src/mcp/builtin/browser.rs`)

- **Error Handling**: `src/features/tools/browser-tools/error-utils.ts`의 에러 메시지 매핑 로직을 `error_guidance.rs`를 활용해 적용.

## 6. 재사용 가능한 연관 코드

- **Legacy Schemas**: `src/lib/web-mcp/modules/**/tools.ts` 파일들을 참조하여 정확한 필드명과 설명을 가져옴.
- **Error Utils**: `src/features/tools/browser-tools/error-utils.ts`의 에러 케이스 분류 로직.

## 7. Test Code 추가 및 수정 가이드

- **Unit Tests**: 각 Rust 모듈(`mod.rs` 또는 별도 test 파일)에 Legacy 스타일의 인자를 넘겼을 때 정상 동작하는지 검증하는 테스트 케이스 추가.
  - 예: `listAssistants`에 `{ "page": 2, "pageSize": 10 }`을 넘겨서 올바른 offset 계산이 되는지 확인.
  - 예: `saveKnowledge`로 호출했을 때 `addContent` 로직이 타는지 확인.

## 8. Clarification Q-list

1.  **Content Store 통합**: `saveKnowledge`는 텍스트 전용이었고 `addContent`는 파일도 지원함. `saveKnowledge`라는 이름으로 파일을 저장하는 것도 허용할 것인가? -> **Yes**, 하위 호환성을 유지하며 기능 확장으로 간주.
2.  **Search Implementation**: `searchServer`의 `weights` (가중치) 기능을 Rust에서 완벽히 구현할 것인가? -> **Phase 1**에서는 스키마 호환성만 맞추고(파라미터 받되 무시), **Phase 2**에서 실제 가중치 로직 구현 권장.
