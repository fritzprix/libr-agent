# Refactoring Plan: Fix Recursive JSON Structure in Tool Responses

**Date**: 2026-01-19 14:45  
**Branch**: dev/0.4.0  
**Status**: ✅ Implementation Complete, Documentation Required

---

## 1. 작업의 목적 (Purpose)

Fix the recursive JSON structure bug in MCP tool responses where tool results are being double-wrapped:

- **Current (Buggy)**: `{"role":"tool", "content":[{"type":"text", "text":"{\n \"content\":[...]\n}"}]}`
- **Expected (Correct)**: `{"role":"tool", "content":[{"type":"text", "text":"✅ createGame..."}]}`

This bug affects all tool responses (both external and builtin MCP servers) and causes:

- Poor UI rendering experience (nested JSON strings need parsing)
- Non-compliance with MCP protocol specification
- Confusion in message history for LLM context

---

## 2. 현재의 상태 / 문제점 (Current State / Issues)

### Root Cause Analysis

**Location**: `src-tauri/src/agent/llm.rs:399`

```rust
// ❌ WRONG: Stringifies entire MCPResponseResult
let content = response
    .result
    .as_ref()
    .and_then(|r| serde_json::to_string_pretty(r).ok())
    .unwrap_or_else(|| "{}".to_string());
```

**Problem Flow**:

1. `MCPResponseResult` contains `MCPResult { content: Vec<MCPContent>, ... }`
2. `to_string_pretty()` converts entire object to JSON **string**: `"{\n \"content\": [...]\n}"`
3. This string is passed to `create_tool_result_message()` which wraps it in `MCPContent::Text`
4. Result: `text { content [ { text: "JSON string" } ] }` (recursive structure)

**Impact Scope**:

- ✅ External MCP servers (stdio/HTTP) - ALL tool responses affected
- ✅ Builtin MCP servers - ALL tool responses affected
- ✅ Chat history - Messages stored with incorrect structure in database
- ✅ UI rendering - Frontend must parse JSON strings unnecessarily

### Evidence from Real-World Trace

User-provided trace from `rpg-mcp-server` confirmed the issue:

```json
{
  "role": "tool",
  "content": [
    {
      "type": "text",
      "text": "{\n  \"content\": [\n    {\"text\": \"✅ createGame...\", \"type\": \"text\"}\n  ]\n}"
    }
  ]
}
```
