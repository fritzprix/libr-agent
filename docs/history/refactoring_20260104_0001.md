# Refactoring Plan: Phase 1 - Planning Module Migration to SeaORM

## 1. 작업의 목적 (Purpose)

Planning 모듈의 데이터베이스 상호작용을 raw SQLx 쿼리에서 **SeaORM**으로 마이그레이션하여 타입 안정성, 유지보수성, 스키마 관리 능력을 향상시킨다. 이는 프로젝트의 장기 아키텍처 목표와 일치하며, LibrAgent의 핵심 기능인 Planning 도구의 안정성을 강화한다.

## 3. Bird's-Eye View (Current Structure)

The `Planning` module consists of:

- **`db.rs`**: Manages SQLite tables (`planning_goals`, `planning_todos`, `planning_scratchpad`) using raw SQL `CREATE TABLE` statements.
- **`models.rs`**: Defines `TodoItem`, `ScratchpadItem` structs with `FromRow` implementations.
- **`goals.rs`**: CRUD operations for goals (INSERT, UPDATE).
- **`todos.rs`**: Complex CRUD for todos, including hierarchical support (parent/child), bulk operations, and status updates.
- **`scratchpad.rs`**: CRUD for scratchpad notes.
- **`context.rs`**: Aggregates data from all tables to build the AI system prompt context.
- **`mod.rs`**: Entry point, initializes the server and handles tool routing.

## 4. Future State / Success Criteria

- **SeaORM Entities**: All tables are defined as SeaORM entities (`Entity`, `Model`, `ActiveModel`).
- **Migrations**: Database schema is managed via SeaORM migration files, not manual SQL execution.
- **Type-Safe Queries**: All database operations use SeaORM's fluent API (`Entity::find()`, `ActiveModel::save()`, etc.).
- **No Raw SQL**: `sqlx::query!` macros and raw strings are removed from the business logic.
- **Functionality Parity**: All tools (`addTodo`, `createGoal`, etc.) behave exactly as before.

```rust
    let mut top_level: Vec<_> = todos.iter().filter(|t| t.parent_id.is_none()).collect();
    for parent in &mut top_level {
        parent.children = todos.iter()
            .filter(|t| t.parent_id == Some(parent.id))
            .collect();
    }
    top_level
}
```
