# Refactoring Plan: Interactive Shell Execution with Secure User Input

**Date**: 2025-11-15
**Version**: 0.2.0
**Author**: AI Assistant

## Executive Summary

### 목표

`execute_shell` 도구에서 sudo 암호와 같은 민감한 사용자 입력을 안전하게 처리하는 Zero-Knowledge Architecture 구현

### 핵심 전략

**보안**: 암호가 Agent의 컨텍스트/로그에 기록되지 않도록 Two-Tool Pattern 사용

**크로스 플랫폼 지원**:

- **Unix/Linux/macOS**: `sudo`, `su` 자동 감지 + stdin 암호 전달 ✅
- **Windows**: 자동 감지 불가 (UAC 제약), 명시적 `require_user_input` 파라미터 사용 ⚠️

**아키텍처**: Two-Tool Pattern

1. **1차 도구** (`execute_shell`): UIResource 반환, execution_id 생성
2. **2차 도구** (`execute_pending_shell`): 사용자 입력 받아 명령 실행
3. **보안**: 암호는 MCP Worker를 통과하지만 Agent 컨텍스트에 기록 안 됨

### 플랫폼별 제약사항

| 기능                 | Unix/Linux/macOS     | Windows            |
| -------------------- | -------------------- | ------------------ |
| 권한 상승 자동 감지  | ✅ `sudo`, `su` 감지 | ❌ UAC는 감지 불가 |
| stdin 암호 전달      | ✅ 지원              | ❌ OS 제약         |
| 사용자 입력 프롬프트 | ✅ UIResource        | ✅ UIResource      |
| Admin 권한 실행      | ✅ sudo + 암호       | ⚠️ UAC GUI 필요    |

### 핵심 메커니즘

1. **sudo -S 플래그 자동 주입**: Backend가 `sudo` 명령어 감지 시 `-S` 플래그 자동 추가 (Agent는 몰라도 됨)
2. **명령어 실행 지연**: 암호 입력 전까지 대기 (PendingExecutions)
3. **Two-Tool Pattern**: 1차 도구 (`execute_shell`) + 2차 도구 (`execute_pending_shell`)
4. **Command Sanitization**: 로그/레지스트리에는 `-S` 플래그 제거된 버전 저장
5. **Timeout 기반 적응 학습**: 자동 감지 실패 시 timeout 발생 → stderr를 Agent에게 투명하게 제공 → Agent가 다음 시도 시 `require_user_input` 설정

### Agent 관점 (투명한 처리)

**Agent가 하는 것**:

```json
{
  "command": "sudo apt install vim", // 일반적인 sudo 명령어
  "require_user_input": true // 또는 자동 감지로 생략 가능 (Unix)
}
```

**Agent가 몰라도 되는 것**:

- ✅ `-S` 플래그 존재 여부 (Backend가 자동 주입)
- ✅ stdin으로 암호 전달하는 메커니즘
- ✅ 2차 도구 호출 (`execute_pending_shell`) - UIResource가 자동 처리
- ✅ PendingExecutions 상태 관리

**Agent가 받는 것**:

```
⏳ Waiting for user input
Execution ID: abc-123
Command: sudo apt install vim  // ← sanitized 버전 (원본과 동일)
```

→ 사용자가 암호 입력 후

```
(Frontend → Agent 통지)
Shell execution complete: abc-123
```

**핵심**: Agent는 일반적인 sudo 명령어만 사용하면 되고, 나머지는 Backend가 자동 처리합니다.

## 1. 작업의 목적`execute_shell` 도구에서 sudo 암호와 같은 민감한 사용자 입력이 필요한 경우, 보안을 최우선으로 하면서도 사용자 친화적인 방식으로 입력을 받을 수 있는 아키텍처를 구현합니다.

**핵심 목표:**

- **Zero-Knowledge Architecture**: 암호가 MCP Request/Response에 절대 노출되지 않도록 보장
- **Secure Channel**: Frontend → Tauri Direct IPC를 통한 암호 전달
- **User-Friendly UX**: UIResource 기반 GUI 입력 폼 제공
- **Auto-Detection**: sudo 명령어 자동 감지 및 프롬프트 생성

/// Pending execution state (server-side only)
#[derive(Debug, Clone)]
pub struct PendingShellExecution {
    pub execution_id: String,
    pub session_id: String,
    pub executable_command: String,  // Command to execute (may include -S flag)
    pub display_command: String,     // Sanitized version for logs/UI
    pub run_mode: String,            // "sync" or "async" from 1st call
    pub timeout: u64,                // Command execution timeout in seconds
    pub created_at: DateTime<Utc>,
}

/// Thread-safe storage
pub struct PendingExecutions(Mutex<HashMap<String, PendingShellExecution>>);

impl PendingExecutions {
    pub fn new() -> Self {
        Self(Mutex::new(HashMap::new()))
    }

    pub fn insert(&self, exec: PendingShellExecution) {
        self.0.lock().unwrap().insert(exec.execution_id.clone(), exec);
    }

    pub fn remove(&self, id: &str) -> Option<PendingShellExecution> {
        self.0.lock().unwrap().remove(id)
    }
}

/// 2차 도구 호출: execute_pending_shell
/// UIResource에서 사용자 입력 완료 후 호출됨
pub async fn handle_execute_pending_shell(&self, args: Value) -> MCPResponse {
    use tokio::io::AsyncWriteExt;
    use std::process::Stdio;

    let execution_id = args["execution_id"].as_str()
        .ok_or_else(|| "Missing execution_id parameter")
        .map_err(|e| return MCPResponse::error(e, None))?;

    let user_input = args["user_input"].as_str()
        .ok_or_else(|| "Missing user_input parameter")
        .map_err(|e| return MCPResponse::error(e, None))?;

    // Retrieve pending execution
    let pending = match self.pending_executions.remove(execution_id) {
        Some(p) => p,
        None => {
            return MCPResponse::error(
                &format!("Unknown or expired execution_id: {}", execution_id),
                None
            );
        }
    };

    // Validate timeout (5 minutes for user input)
    const USER_INPUT_TIMEOUT_SECS: i64 = 300;
    let elapsed = Utc::now()
        .signed_duration_since(pending.created_at)
        .num_seconds();
    if elapsed > USER_INPUT_TIMEOUT_SECS {
        return MCPResponse::error("Execution request expired. Please retry.", None);
    }

    // 🔧 AUTO-INJECT: Add -S flag for sudo commands (Agent doesn't know about it)
    let final_command = if pending.executable_command.trim_start().starts_with("sudo ") {
        // Check if -S flag already exists (defensive programming)
        if pending.executable_command.contains("sudo -S ") {
            pending.executable_command.clone()
        } else {
            // Insert -S flag after 'sudo'
            pending.executable_command.replacen("sudo ", "sudo -S ", 1)
        }
    } else {
        pending.executable_command.clone()
    };

    // Execute command with stdin
    #[cfg(unix)]
    let mut cmd = {
        let mut c = tokio::process::Command::new("sh");
        c.arg("-c").arg(&final_command);
        c
    };

    #[cfg(windows)]
    let mut cmd = {
        let mut c = tokio::process::Command::new("powershell");
        c.args(["-NoProfile", "-NonInteractive", "-Command", &final_command]);
        c
    };

    cmd.stdin(Stdio::piped());
    cmd.stdout(Stdio::piped());
    cmd.stderr(Stdio::piped());

    let mut child = cmd.spawn()
        .map_err(|e| return MCPResponse::error(&format!("Failed to spawn: {}", e), None))?;

    // Write user input to stdin
    if let Some(mut stdin) = child.stdin.take() {
        // CRITICAL: Write password and close stdin
        if let Err(e) = stdin.write_all(user_input.as_bytes()).await {
            return MCPResponse::error(&format!("Failed to write to stdin: {}", e), None);
        }
        if let Err(e) = stdin.write_all(b"\n").await {
            return MCPResponse::error(&format!("Failed to write newline: {}", e), None);
        }
        drop(stdin); // Close stdin to signal EOF
    }

    // 🔒 SECURITY: Clear user_input from memory
    drop(user_input);

    // Execute based on run_mode from 1st call
    if pending.run_mode == "sync" {
        // Wait for completion with timeout
        let output = match tokio::time::timeout(
            Duration::from_secs(pending.timeout),
            child.wait_with_output()
        ).await {
            Ok(Ok(output)) => output,
            Ok(Err(e)) => return MCPResponse::error(&format!("Process error: {}", e), None),
            Err(_) => return MCPResponse::error("Command execution timeout", None),
        };

        // 🔒 SECURITY: Log sanitized command only
        tracing::info!(
            "Interactive shell executed: {} (session: {}, exit: {:?})",
            pending.display_command,
            pending.session_id,
            output.status.code()
        );

        // Return stdout/stderr to Agent
        MCPResponse::success(serde_json::json!({
            "exit_code": output.status.code(),
            "stdout": String::from_utf8_lossy(&output.stdout).to_string(),
            "stderr": String::from_utf8_lossy(&output.stderr).to_string(),
        }))
    } else {
        // Async mode: return process_id immediately
        let process_id = uuid::Uuid::new_v4().to_string();

        // Register process (spawn monitoring task)
        // ... (similar to existing execute_shell_async logic)

        MCPResponse::success(serde_json::json!({
            "process_id": process_id,
            "message": "Command running in background"
        }))
    }
}

    let require_input = args["require_user_input"].as_bool().unwrap_or(false);
    let auto_sudo = raw_command.trim_start().starts_with("sudo ");

    if require_input || auto_sudo {
        return self.handle_interactive_shell(raw_command, &args).await;
    }

    // 🔒 SECURITY: Sanitize command for ProcessRegistry and logs
    let sanitized_command = sanitize_command_for_logging(raw_command);

    // 기존 sync/async 로직
    // ProcessEntry 등록 시 sanitized_command 사용
    let entry = terminal_manager::ProcessEntry {
        id: process_id.clone(),
        session_id: session_id.clone(),
        command: sanitized_command.clone(), // ← sanitized 버전
        // ... rest of fields
    };

    // 로그 기록 시에도 sanitized_command 사용
    info!(
        "Isolated shell command executed: {} (session: {}, exit: {:?})",
        sanitized_command,  // ← sanitized 버전
        session_id,
        exit_code
    );
}

// 새 메서드 추가
async fn handle_interactive_shell(&self, command: &str, args: &Value) -> MCPResponse {
    let execution_id = uuid::Uuid::new_v4().to_string();
    let session_id = self.session_manager.get_current_session()
        .unwrap_or_else(|| "default".to_string());

    // 🔒 SECURITY: Sanitize command for storage/logging
    let sanitized_command = sanitize_command_for_logging(command);

    // Extract run_mode from 1st call (will be used in 2nd call)
    let run_mode = args["run_mode"].as_str().unwrap_or("sync").to_string();

    // Store pending execution
    let pending = PendingShellExecution {
        execution_id: execution_id.clone(),
        session_id,
        executable_command: command.to_string(), // Will be executed (may get -S flag)
        display_command: sanitized_command.clone(), // For logs/UI
        run_mode,  // Store for 2nd call
        timeout: args["timeout"].as_u64().unwrap_or(30), // Command execution timeout
        created_at: Utc::now(),
    };

    self.pending_executions.insert(pending);

    // Build UIResource with platform-aware prompt
    let (prompt, input_type) = self.get_prompt_config(command, args);
    let html = self.build_shell_input_ui(&execution_id, prompt, input_type);

    // Return multipart response
    // 🔒 SECURITY: Use sanitized command in MCP response text
    MCPResponse::multipart(vec![
        MCPContent::text(format!(
            "⏳ Waiting for user input\nExecution ID: {}\nCommand: {}",
            execution_id, sanitized_command  // ← sanitized 버전 사용
        )),
        MCPContent::ui_resource(UIResource {
            uri: format!("ui://shell-input/{}", execution_id),
            html,
            mimeType: Some("text/html".to_string()),
        }),
    ])
}

// Platform-aware prompt configuration
fn get_prompt_config<'a>(&self, command: &str, args: &'a Value) -> (&'a str, &'a str) {
    // Check if privilege escalation detected (Unix only)
    let is_privilege_cmd = self.detect_privilege_escalation(command);

    if is_privilege_cmd {
        ("Enter your sudo password:", "password")
    } else {
        // Use custom prompt from args
        let prompt = args["input_prompt"].as_str().unwrap_or("Enter input:");
        let input_type = args["input_type"].as_str().unwrap_or("text");
        (prompt, input_type)
    }
}

async fn get_partial_stderr(child: &mut tokio::process::Child) -> String {
    if let Some(mut stderr) = child.stderr.take() {
        let mut buffer = Vec::new();
        // Try to read available data (non-blocking)
        if let Ok(_) = tokio::time::timeout(
            Duration::from_millis(100),

### 4.5 Frontend: 수정 불필요

UIResource에서 `window.postMessage({ type: 'call_tool', tool: 'execute_pending_shell' })`를 호출하면, MCP Worker가 자동으로 도구 호출을 처리합니다.

기존 MCP Worker의 도구 호출 메커니즘을 그대로 사용하므로, **별도의 event listener 코드 추가가 불필요**합니다.

**이유**:

- MCP Worker는 이미 `postMessage`로 전달된 `call_tool` 이벤트를 처리하는 로직이 있음
- `execute_pending_shell` 도구는 일반 MCP 도구와 동일하게 처리됨
- Agent는 도구 호출 결과를 MCP Response로 자동 수신

## 9. 추가 분석 과제

다음 항목은 구현 중 추가 검토 필요:

### 9.1 Windows 호환성 및 권한 상승 감지

#### 문제점: 플랫폼별 권한 상승 메커니즘 차이

**Unix/Linux/macOS:**

- `sudo` 명령어 사용
- 문자열 감지 가능: `command.starts_with("sudo ")`
- stdin으로 암호 전달 가능

**Windows:**

- UAC (User Account Control) 사용
- `runas` 명령어 (암호 프롬프트 별도 창)
- PowerShell: `Start-Process -Verb RunAs` (GUI 프롬프트)
- 명령어 문자열만으로 감지 **불가능**

#### 개선된 감지 전략

**Option 1: 명시적 파라미터 방식 (권장)**

```rust
// Agent가 명시적으로 지정
{
  "command": "apt-get update",
  "require_user_input": true,
  "input_type": "password",
  "input_prompt": "Enter sudo password"
}
```

**Option 2: 플랫폼별 패턴 매칭**

```rust
fn needs_privilege_escalation(command: &str) -> bool {
    #[cfg(unix)]
    {
        command.trim_start().starts_with("sudo ")
            || command.trim_start().starts_with("su ")
    }

    #[cfg(windows)]
    {
        // Windows는 자동 감지 불가능
        // runas, Start-Process -Verb RunAs 등도
        // GUI 프롬프트를 띄우므로 stdin 사용 불가
        false
    }
}
```

**Option 3: Heuristic 분석 (복잡, 비권장)**

- 시스템 디렉토리 접근 (`/etc/`, `C:\Windows\System32\`)
- 포트 바인딩 (`< 1024`)
- 파일 권한 변경 (`chmod`, `chown`)
- 문제: False positive 많음, 유지보수 어려움

#### 권장 구현 방식

```rust
// code_execution.rs
pub async fn handle_execute_shell(&self, args: Value) -> MCPResponse {
    let raw_command = args["command"].as_str().unwrap();
    let require_input = args["require_user_input"].as_bool().unwrap_or(false);

    // Platform-specific auto-detection (Unix only)
    let auto_detect_privilege = self.detect_privilege_escalation(raw_command);

    if require_input || auto_detect_privilege {
        return self.handle_interactive_shell(raw_command, &args).await;
    }

    // Normal execution
}

#[cfg(unix)]
fn detect_privilege_escalation(&self, command: &str) -> bool {
    let trimmed = command.trim_start();
    trimmed.starts_with("sudo ") || trimmed.starts_with("su ")
}

#[cfg(windows)]
fn detect_privilege_escalation(&self, _command: &str) -> bool {
    // Windows UAC는 자동 감지 불가능
    // Agent가 require_user_input을 명시적으로 설정해야 함
    false
}
```

### 9.2 Multiple Prompts - 현재 설계의 명시적 한계

**현재 구현의 제약사항**: 이 기능은 **단일 사전 입력(Single Pre-execution Input)만 지원**합니다.

**기술적 이유**:

1. `stdin.write_all(user_input).await?;`
2. `drop(stdin);` ← stdin 즉시 닫음
3. `child.wait_with_output().await?;` ← 프로세스 종료 대기

stdin을 닫은 후에는 추가 입력이 불가능하므로, 다음과 같은 시나리오는 **지원되지 않습니다**:

**❌ 불가능한 시나리오**:

- `sudo apt-get install` → password (1차 입력) → y/n confirmation (2차 입력)
- Interactive shell prompts with multiple user responses
- Scripts requiring sequential user confirmations

**현재 지원 범위**:

- ✅ 명령 실행 **전** 단일 입력 (예: sudo password)
- ❌ 명령 실행 **중** 다중 상호작용

**해결 방법 (향후)**:

- PTY (Pseudo-Terminal) 기반 실행 필요
- stdin을 열린 상태로 유지하며 bidirectional communication 지원
- 현재 설계와는 완전히 다른 아키텍처 필요

**결론**: Multiple prompts는 현재 설계의 **근본적 한계**이며, 추가 기능이 아닙니다.

## 10. Clarification Q-list

구현 전 사용자 의사결정이 필요한 항목:

### Q1. Auto-Detection 범위 및 플랫폼 차이

**질문**: 권한 상승이 필요한 명령어를 어떻게 감지할까요?

**Unix/Linux/macOS:**

- `sudo`, `su` 명령어 → 문자열 패턴 매칭으로 자동 감지 가능
- stdin으로 암호 전달 가능
- 추가 감지 대상:
  - `doas` (OpenBSD sudo 대안)
  - `pkexec` (PolicyKit)

**Windows:**

- UAC (User Account Control) → **자동 감지 불가능**
- `runas`, `Start-Process -Verb RunAs` → 모두 GUI 프롬프트 발생
- stdin 암호 전달 불가능 (OS 제약)

**권장 결정**:

1. **Unix**: `sudo`, `su` 자동 감지 구현 ✅
2. **Windows**: 자동 감지 비활성화, Agent가 `require_user_input` 명시적 설정
3. **Tool Description**: 플랫폼별 제약사항 명시

**코드 예시**:

```rust
#[cfg(unix)]
fn detect_privilege_escalation(command: &str) -> bool {
    let patterns = ["sudo ", "su ", "doas ", "pkexec "];
    patterns.iter().any(|p| command.trim_start().starts_with(p))
}

#[cfg(windows)]
fn detect_privilege_escalation(_command: &str) -> bool {
    false // Windows UAC는 자동 감지 불가
}
```

#### 답변: sudo / su 자동 감지 for xnix, windows는 명시적 설정, input 입력의 필요성 여부를 timeout을 통해 점진적으로 진단할 수 있음. 사용자 입력이 없으면 실행 시 timeout, 이후 종료 조건을 조사 (stdio / err), 다음 시도시 명시적으로 사용자 입력 요청

### Q2. Timeout 정책

**질문**: Pending execution의 타임아웃은?

- 현재 제안: 5분
- 너무 짧으면: 사용자가 다른 작업 중일 때 불편
- 너무 길면: 메모리 누수 위험

**권장**: 5분 + 환경변수로 조정 가능

#### 답변: 5분 looks good

### Q3. UIResource vs Native Dialog

**질문**: Tauri의 native dialog API를 사용할까요?

- **UIResource 장점**: 커스터마이징 자유, 일관된 UX
- **Native Dialog 장점**: OS 표준, 보안성 높음

**권장**: UIResource (기존 패턴과 일관성)

#### 답변: UIResouce preferred

### Q4. Async Mode와의 조합

**질문**: `run_mode: async`와 `require_user_input: true`를 동시에 허용?

**현재 설계**:

- 1차 호출: `execute_shell`에서 `run_mode`를 `PendingShellExecution`에 저장
- 2차 호출: `execute_pending_shell`에서 저장된 `run_mode`에 따라 sync/async 실행

**답변**: **허용됨** ✅

- **sync mode**: 2차 도구 호출 시 명령 실행 완료까지 대기 → stdout/stderr 반환
- **async mode**: 2차 도구 호출 시 즉시 process_id 반환 → 백그라운드 실행

**Agent 관점**:

1. 1차 호출 (`execute_shell`): UIResource 받고 즉시 다음 작업 진행 가능 (항상 비차단)
2. 2차 호출 (`execute_pending_shell`): `run_mode`에 따라 sync/async 동작

**권장**:

- `run_mode`는 명령어 **실행**의 sync/async를 결정 (2차 호출)
- UIResource를 통한 사용자 입력 대기는 별개의 프로세스 (1차 호출 완료 후)

### Q5. Windows에서 Admin 권한 필요 명령어 처리

**질문**: Windows에서 관리자 권한이 필요한 명령어는 어떻게 처리할까요?

**현재 상황**:

- Windows는 stdin으로 암호 전달 불가능
- UAC 프롬프트는 시스템 GUI로만 표시됨
- `runas /user:Administrator` 도 별도 창에서 암호 요청

**선택지**:

1. **현상 유지**: UAC 프롬프트 그대로 사용
   - 장점: Windows 표준 동작
   - 단점: Agent가 제어 불가, 비동기 실행 어려움

2. **사전 안내**: Tool description에 Windows 제약사항 명시
   - "Windows: Admin privileges require manual UAC approval"
   - Agent가 사용자에게 수동 실행 안내

3. **Elevated 세션 사전 시작**: LibrAgent 자체를 관리자 권한으로 실행
   - 장점: 추가 UAC 없이 실행 가능
   - 단점: 보안 위험, 사용자가 거부할 가능성

**권장**: 선택지 2 (명시적 안내)

- `require_user_input` 지원 범위:
  - ✅ 스크립트 확인 프롬프트 (y/n)
  - ✅ Read-Host 같은 일반 텍스트 입력
  - ✅ 비권한 수준 암호 입력
  - ❌ 관리자 암호 입력 (UAC 사용)
- Windows에서 관리자 권한 필요 시 Agent가 사용자에게 안내
- Tool description에 플랫폼별 차이 명확히 기재

#### 답변: 선택지 2번(사전 안내)
