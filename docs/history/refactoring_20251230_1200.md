# Refactoring Plan: Align Rust Tools with Legacy Schema

## 1. Purpose

To ensure full backward compatibility and seamless migration for AI agents by aligning the schemas and behaviors of the new Rust-based MCP tools (`src-tauri/src/mcp/builtin/*`) with the legacy TypeScript implementations (`src/lib/web-mcp/modules/*`). This eliminates "hallucinations" caused by LLMs using legacy parameter names against the new backend.

## 2. Current Status / Problems

The migration to Rust introduced several schema deviations:

- **Assistant Manager**: Parameter names changed (`mcpServerIds` → `mcpServers`, `allowedBuiltInServiceAliases` → `tools`). Pagination changed (`page`/`pageSize` → `limit`/`offset`).
- **Content Store**: Tool names and signatures changed (`saveKnowledge` → `addContent`, `searchKnowledge` → `keywordSimilaritySearch`).
- **MCP Manager**: `searchServer` lost advanced parameters (`searchMode`, `weights`) present in legacy.
- **Browser**: `extractContent` implementation changed from `TurndownService` to `html2md`, potentially affecting markdown quality.

## 3. Architecture Summary (Bird's-eye View)

- **Legacy**: TypeScript modules in `src/lib/web-mcp/modules/` define tools and handle logic using `Dexie` (IndexedDB) and local services.
- **New**: Rust modules in `src-tauri/src/mcp/builtin/` define tools using `MCPTool` structs and handle logic using `SQLx` (SQLite) and native Tauri services.
- **Goal**: The Rust `MCPTool` definitions (input schemas) must match the Legacy definitions exactly where possible.

## 4. Target State / Acceptance Criteria

- **Assistant Tools**: `createAssistant` accepts `mcpServerIds` and `allowedBuiltInServiceAliases`. `listAssistants` accepts `page` and `pageSize`.
- **Content Tools**: `saveKnowledge` and `searchKnowledge` tools exist in Rust with legacy signatures.
- **MCP Manager**: `searchServer` accepts legacy parameters (even if ignored gracefully).
- **Validation**: Existing agent prompts (which use legacy schemas) must work without modification against the Rust backend.

**Task**: Rename parameters and fix pagination.

    MCPTool {
        name: "builtin_assistant__createAssistant".to_string(),
        // ...
        input_schema: serde_json::from_value(json!({
            "type": "object",
            "properties": {
                // ... existing fields ...
                "mcpServerIds": { // Renamed from mcpServers
                    "type": "array",
                    "items": { "type": "string" },
                    "description": "List of enabled MCP server IDs"
                },
                "allowedBuiltInServiceAliases": { // Renamed from tools
                    "type": "array",
                    "items": { "type": "string" },
                    "description": "List of allowed built-in service aliases"
                }
                // Note: Keep modelProvider etc. as optional/advanced fields

        // ...
    }

## 7. Test Plan

1.  **Schema Validation**:
    - Create a test that compares the JSON schema output of Rust tools against a snapshot of the Legacy tool schemas.
2.  **Functional Testing**:
    - Use the "Refactoring Agent" or manual testing to call `createAssistant` with `mcpServerIds` and verify it persists correctly in the SQLite DB.
    - Call `saveKnowledge` with `title` and `tags` and verify it appears in `listContent` with correct metadata.

## 8. Clarification Q-list

- **Model Config**: Legacy `createAssistant` does not include `modelProvider`, `modelName`, etc. Rust does.
  - _Decision_: Keep them in Rust schema but make them optional. This extends functionality without breaking legacy compatibility (as legacy calls won't provide them, and Rust handles defaults).
- **Browser `extractContent`**: Quality verification of `html2md` vs `Turndown`.
  - _Action_: Defer to a separate task. For now, ensure the _interface_ (`sessionId`) remains the same (it is).
