# Refactoring Plan: Circuit Breaker for Repetitive Tool Calls

## 1. 작업의 목적

- **무한 루프 방지**: AI 에이전트가 동일한 도구와 파라미터를 반복적으로 호출하는 경우(예: 에러가 나는데 계속 같은 시도를 함)를 감지하여 실행을 차단함.
- **사용자 개입 유도**: Circuit Breaker UI를 통해 사용자에게 상황을 알리고, 'Resume' 버튼을 통해 사용자가 명시적으로 재개를 승인하도록 함.
- **가이드 제공**: 재개 시 에이전트에게 반복 호출 사실을 알리고 다른 방법을 시도하도록 가이드하여 문제 해결 능력을 높임.

## 2. 현재의 상태 / 문제점

- **보호 장치 부재**: 현재 `use-tool-processor.ts`는 에이전트가 요청하는 모든 도구 호출을 그대로 실행함.
- **리소스 낭비**: 에이전트가 루프에 빠지면 토큰과 컴퓨팅 리소스가 낭비되고, 사용자는 중단하기 위해 수동으로 개입해야 함.

## 3. 관련 코드의 구조 및 동작 방식 Summary

- **Tool Processor** (`src/hooks/use-tool-processor.ts`): 도구 호출 메시지를 감지하고 실행하는 핵심 로직.
- **UI Tools** (`src/lib/web-mcp/modules/ui-tools/`): 사용자 인터랙션을 위한 도구 모음.
- **Message Flow**: Agent -> Tool Call -> Processor -> Execute -> Result -> Agent.

## 4. 변경 이후의 상태 / 해결 판정 기준

### New Tools (`ui-tools`)

- **`circuitBreak`**: 시스템이 내부적으로 호출하는 도구. 반복 호출 감지 시 실행되며, 경고 UI를 렌더링함.
- **`dismissCircuitBreak`**: 사용자가 UI에서 'Resume' 버튼을 클릭했을 때 호출되는 도구. 에이전트에게 가이드 메시지를 반환함.

### Processor Logic (`use-tool-processor.ts`)

- **감지 로직**: 최근 실행된 도구의 이름과 파라미터 해시를 추적. 연속 3회(기본값) 이상 동일하면 차단.
- **개입 로직**: 차단 시 원래 도구 대신 `circuitBreak` 도구를 실행하여 결과를 반환.

### B. Tool Processor (`src/hooks/use-tool-processor.ts`)

#### `useToolProcessor` 수정

```typescript
// State for tracking history
const toolHistoryRef = useRef<{ signature: string; count: number } | null>(
  null,
);

// Inside execute function loop
for (const toolCall of tcMessage.tool_calls.map(fixInvalidToolCall)) {
  const toolName = toolCall.function.name;
  const args = toolCall.function.arguments;

  // 1. Repetition Detection
  const currentSignature = `${toolName}:${args}`;
  let isLooping = false;

  if (toolHistoryRef.current?.signature === currentSignature) {
    toolHistoryRef.current.count += 1;
    if (toolHistoryRef.current.count >= 3) {
      // Max 3 attempts
      isLooping = true;
    }
  } else {
    toolHistoryRef.current = { signature: currentSignature, count: 1 };
  }

  // 2. Interception
  if (isLooping) {
    logger.warn('Circuit breaker triggered', {
      toolName,
      count: toolHistoryRef.current.count,
    });

    // Inject circuitBreak tool call
    const circuitBreakCall = {
      ...toolCall,
      function: {
        name: 'circuitBreak',
        arguments: JSON.stringify({
          toolName,
          repetitionCount: toolHistoryRef.current.count,
          args,
        }),
      },
    };

    // Execute circuitBreak instead
    const mcpResponse = await executeToolCallRef.current(circuitBreakCall);

    // ... process response as usual ...
    // Reset history after triggering to avoid infinite blocking if user resumes and agent insists
    toolHistoryRef.current = null;
  } else {
    // Normal execution
    const mcpResponse = await executeToolCallRef.current(toolCall);
    // ...
  }
}
```

### Circular Dependency Detection Algorithm

```typescript
// DFS-based cycle detection with recursion stack tracking
function dfs(nodeId: number): number[] | null {
  visited.add(nodeId);
  recursionStack.add(nodeId);
  path.push(nodeId);

  for (const neighbor of neighbors) {
    if (!visited.has(neighbor)) {
      const cycle = dfs(neighbor);
      if (cycle) return cycle;
    } else if (recursionStack.has(neighbor)) {
      // Back edge found - cycle detected!
      return extractCycle(path, neighbor);
    }
  }

  recursionStack.delete(nodeId);
  path.pop();
  return null;
}
```
