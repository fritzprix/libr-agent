**Date**: January 16, 2026 09:00

## 1. 작업의 목적 (Purpose of Work)

Refactor the Workspace builtin tool (`src-tauri/src/mcp/builtin/workspace/`) to:

1. **Improve Maintainability**: Break down large files (1343 and 2007 lines) into focused, single-responsibility modules
2. **Standardize Patterns**: Achieve consistency in success response handling and cache invalidation
3. **Enhance Testing**: Add comprehensive test coverage for error handling, caching, and session lifecycle
4. **Future-Proof Architecture**: Prepare codebase for easy feature additions and reduced cognitive load

### Success Metrics:

- All files < 500 lines (with few exceptions for data structures)
- 100% consistent use of `SuccessHint` pattern for success responses
- Cache invalidation applied to all state-changing operations
- Test coverage > 70% for critical paths

### 3.2 Data Flow Example (File Read)

```
User Input
  ↓
Chat → executeToolCall("readFile", {path: "src/main.rs"})
  ↓
Frontend → safeInvoke("call_tool", ["readFile", args])
  ↓
Rust Backend → agent/llm.rs → call BuiltinMCPServer::call_tool()
  ↓
WorkspaceServer::call_tool() [mod.rs line 1239]
  ├─ Match tool_name "readFile"
  ├─ Call self.handle_read_file(args, session_id)
  │
  └─ WorkspaceServer::handle_read_file() [file_operations.rs]
     ├─ Validate path (empty check, security check, type check)
     ├─ Read file with line range support
     ├─ Spawn blocking for large files (>1MB)
     └─ Return SuccessHint with formatted content
  ↓
MCPResult {
  content: [MCPContent::text("File content...")]
  structured_content: {content, path, size}
}
  ↓
Frontend → Displays formatted file content
```

### 3.3 Session Isolation Flow

```
Agent Session Created
  ↓
AgentSessionManager creates WorkspaceServer instance [unique per session]
  ├─ Isolated process_registry (per-server)
  ├─ Isolated shell_manager (per-server)
  └─ session_id stored in WorkspaceServer
  ↓
Handler execution with session_id parameter
  ├─ Target session ID = param OR server.session_id
  ├─ Process registry filtered by session_id
  └─ Shell manager filtered by session_id
  ↓
Session End
  └─ on_session_end() called → cleans all resources [EXCELLENT]
```

const CACHE_TTL_SECS: u64 = 5;

    if let Some((cached_prompt, last_update)) = guard.as_ref() {
        if last_update.elapsed().as_secs() < CACHE_TTL_SECS {

## Implementation Notes

### For Implementor

1. **Start with Step 1-3** (file splitting) - largest effort, highest visibility
2. **Use `find_referencing_symbols`** to track all call sites when moving functions
3. **Create handler modules in this order**:
   - `handlers/mod.rs` (re-exports only)
   - `handlers/file.rs` (lowest risk - mostly pure functions)
   - `handlers/code.rs` (medium risk - depends on process registry)
   - `handlers/terminal.rs` (medium risk - complex state tracking)
   - `handlers/export.rs` (lowest risk - small, isolated)

4. **Test after each step**:
   - Compile check: `cargo check`
   - Rust linting: `pnpm rust:clippy`
   - Run existing tests: `cargo test`

5. **Before committing**:
   - Run `pnpm refactor:validate` (full pipeline)
   - Create integration test for end-to-end file read/write
