## 1. 실행 요약

### 이 문서의 목적

세 가지 별도 데모 컨셉(Marketing, Technical, Investor)을 **단일 8분 Live Demo 스크립트**로 통합합니다.
한 번의 시연으로 세 가지 관점(사용자 가치, 기술적 신뢰, 비즈니스 가능성)을 모두 증명합니다.

### 핵심 메시지 3줄

```
1. "Cursor는 도구. LibrAgent는 워크스페이스."
2. "로컬 우선 + 완전 오픈소스 + MCP 표준 + 다에이전트 + 온프레미스 — 유일한 조합."
3. "기능은 이미 만들었습니다. 이제 성장만 하면 됩니다."
```

### 타겟 관중별 핵심 질문

| 관중 | 데모가 답해야 할 질문 | 섹션 |
|------|----------------------|------|
| **사용자**(DevDan, SecureSara, ResearchRaj, StartupSam, EnterpriseElena) | "이건 내 문제다" | Section 1 + 2 |
| **기술자**(엔지니어, 아키텍트, OSS 기여자) | "아키텍처가 설정보다 낫다" | Section 2 |
| **투자자**(VC, Angel, CVC) | "왜 이 팀에 $2M을 던져야 하는가" | Section 3 + 4 |

### 성공 기준 (KPI)

| 관중 | 성공 신호 |
|------|----------|
| **사용자** | "무료로 내 PR 한 번 리뷰해보기" 클릭 → GitHub OAuth → 즉시 실행 |

## 4. Section 2: Core Demo — 4 Wow Moments (0:30–4:00)

### Wow Moment 1: 세션 격리 — 코드 레벨에서 증언 (0:30–1:30)

#### 화면 구성

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   [터미널 2분할: 세션 A vs 세션 B]                               │
│                                                                 │
│   ┌──────────────────┐    ┌──────────────────┐                 │
│   │ Session A         │    │ Session B         │                 │
│   │ sess_a_001        │    │ sess_b_002        │                 │
│   │                   │    │                   │                 │
│   │ planning add      │    │ planning add      │                 │
│   │ "Task A"          │    │ "Task B"          │                 │
│   │ → todo_a_1        │    │ → todo_b_1        │                 │
│   │                   │    │                   │                 │
│   │ planning list     │    │ planning list     │                 │
│   │ → [todo_a_1] A    │    │ → [todo_b_1] B    │                 │
│   │                   │    │                   │                 │
│   │ ← A의 데이터      │    │ ← B의 데이터      │                 │
│   │    B에 절대 안보임 │    │    A에 절대 안보임 │                 │
│   └──────────────────┘    └──────────────────┘                 │
│                                                                 │
│   [코드 오버레이: MCPServiceProxy 구조]                         │
│   ┌─────────────────────────────────────────────────────────┐  │
│   │ pub struct MCPServiceProxy {                             │  │
│   │     session_id: String,                                  │  │
│   │     builtin_servers: HashMap<String, Box<dyn            │  │
│   │         BuiltinMCPServer>>,                              │  │
│   │     session_stdio_tool_cache: Arc<RwLock<...>>,          │  │
│   │     session_http_tool_cache: Arc<RwLock<...>>,           │  │
│   │ }                                                        │  │
│   └─────────────────────────────────────────────────────────┘  │
│                                                                 │
│   ✅ 핵심: 각 세션이 별도 HashMap, 별도 캐시, 별도 매니저        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 스피커 노트

> "세션 A에서 `planning add "Task A"` — 세션 B에서 `planning list`를 호출해도, A의 todo는 절대 안 보입니다.
>
> 이건 설정이 아닙니다. 아키텍처입니다.
>
> [코드 오버레이]
> `MCPServiceProxy`가 세션마다 별도 `HashMap`을 생성합니다. 별도 캐시. 별도 매니저.
> 세션 A의 데이터가 세션 B에 침투할 수 있는 경로는 아예 없습니다.
>
> 마케팅 관점에서는 '개인 비서와 팀 비서가 동시에 작동'하는 것이고,
> 기술 관점에서는 `HashMap<String, Box<dyn BuiltinMCPServer>>`로 구현된 격리이고,
> 투자자 관점에서는 '보안 위반 리스크 제로'라는 의미입니다."

#### 관중별 반응 유도

| 관중 | 유도 질문 |

| **DevDan** | "나도 세션 여러 개 열 수 있구나" |

│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### 스피커 노트

> "대부분의 AI 에이전트 플랫폼은 도구 수가 20-50개에 그칩니다. LibrAgent는 170개 이상 — 그리고 UI가 깨지지 않습니다.
>
> [타임라인 표시]
> 이 모든 도구 호출이 실시간으로 스트리밍되고 있습니다.
>
> 핵심은 아키텍처입니다. 프론트엔드는 상태를 소유하지 않습니다. 백엔드가 발신하는 `AgentEvent`를 구독할 뿐입니다.
>
> ```typescript
> listen('agent:event', (event) => {
>   switch (event.type) {
>     case 'toolExecutionStarted': addToolCallToMessage(event.toolName); break;
>     case 'toolExecutionCompleted': updateToolCallResult(...); break;
>   }
> });
> ```
>
> 상태less 구독 — 이것이 170개 도구를 UI 깨짐 없이 처리하는 비결입니다."

#### 스피커 노트

> "외부 MCP 서버를 플러그인처럼 추가하고 제거합니다.
>
> [상태 1 → 2 → 3 시연]
> GitHub MCP를 추가하면 즉시 도구 목록에 반영 — 제거하면 즉시 사라집니다.
>
> [JSON 설정 표시]
> 설정은 이 5줄. stdio, HTTP, SSE 세 가지 프로토콜을 모두 지원합니다.
>
> 개발자 도구 스크립트부터 사내 REST API, 실시간 검색 스트리밍까지 — 표준화된 프로토콜 하나로 통합됩니다.
>
> 이것이 MCP 표준의 힘입니다. Anthropic이 정의한 표준이 LibrAgent의 생태계 확장 엔진입니다."
