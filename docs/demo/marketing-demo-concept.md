## 1. 개요

### 1.1 데모의 목적

LibrAgent 데모는 **30초 안에 "이건 내 문제다"**를 느끼게 해야 합니다.
사용자가 3분 안에 "Pro로 전환하고 싶다" 또는 "팀에 소개해야겠다"는 행동을 취하도록 설계합니다.

### 1.2 데모 원칙

| 원칙 | 내용 |
|---|---|
| **Show, don't tell** | 기능 설명 대신 실제 작업 흐름을 보여줌 |
| **30-second hook** | 첫 30초 안에 핵심 가치를 전달 |
| **Persona-first** | 모든 데모는 페르소나의 언어로 시작 |
| **One click away** | 전환은 데모 내 어디에서나 즉시 가능 |
| **Shareable moments** | 각 데모에서 1~2개의 "Wow moment"를 반드시 포함 |

### 1.3 데모 형식

| 형식 | 길이 | 사용처 | 제작 우선순위 |
|---|---|---|---|
| **Live Interactive** | 5~8분 | 웹미팅, Product Hunt, 투자자 미팅 | P0 |
| **Screen Recording** | 2~3분 | 랜딩 페이지, 블로그, YC Directory | P0 |
| **15s Clip** | 15초 | X/Twitter, TikTok, YouTube Shorts | P1 |
| **Micro-demo** | 30초 | 이메일 시드, Cold DM, Reddit 댓글 | P2 |

## 2. 5개 페르소나별 최적 데모 시나리오

### 2.1 Solo Developer ("DevDan") — 코드 리뷰 자동화

**페르소나 프로필:** 풀스택 개발자, 28세, 개인 프로젝트 3개 병행, GitHub에 매일 push. 기존에는 PR 올릴 때마다 친구한테 "봐줄 수 있어?" DM을 보냄.

#### 데모 시나리오: "PR을 던지면, 30초 만에 리뷰가 와요"

| 시간 | 화면 | 네레이션 (DevDan의 언어) |
|---|---|---|
| **0:00–0:10** | `git push` 후 GitHub PR 생성 | "PR 올리고 나면, 이제 친구한테 DM 안 보내도 돼요." |
| **0:10–0:25** | LibrAgent 창에서 Code Review 에이전트 시작 | "이제 '코드 리뷰해줘' 한 마디면..." |
| **0:25–0:45** | 에이전트가 `git diff` → 파일 읽기 → lint 체크 → 패턴 분석 | "...에이전트가 코드를 읽고, 변수명부터 아키텍처까지 다 봐줘요." |
| **0:45–1:00** | 리뷰 결과 — 개선 제안, 잠재적 버그, 테스트 커버리지 제안 | "단순히 '이거 고쳐'가 아니라, 왜 고쳐야 하는지, 어떻게 테스트해야 하는지까지." |
| **1:00–1:15** | **Wow Moment:** 에이전트가 테스트 파일도 함께 생성 | "테스트 코드까지 써줘요. 이건 좀..." |
| **1:15–1:30** | "무료로 3번의 에이전트 실행" vs "Pro 무제한" 비교 | "무료로 3번 해본 다음, Pro로 전환하면 무제한. 솔직히 3번이면 충분할 거예요." |

**왜 이 시나리오가 잡 hitting인가?**
- DevDan이 매일 겪는 "PR 리뷰 의뢰 → 기다림 → 피드백 받음"의 피로도를 정확히 타격
- "친구한테 DM 안 보내도 돼요" — 개발자 사회의 암묵적 고통을 언어화
- 결과물이 단순히 "코드 수정 제안"이 아니라 **테스트 코드 생성**까지 포함 → "이건 좀..."

**CTA:** "무료로 내 PR 한 번 리뷰해보기" → GitHub OAuth → 즉시 코드 리뷰 실행

### 2.2 보안/프라이버시 관여자 ("SecureSara") — 온프레미스 + 세션 격리

**페르소나 프로필:** 금융/헬스케어 분야 시니어 엔지니어, 온프레미스 LLM 도입 검토 중. 클라우드 AI 사용 시 데이터 유출 리스크로 밤에 잠 못 짐.

#### 데모 시나리오: "데이터는 당신의 기기에서, 단 한 번도 나가지 않습니다"

| 시간 | 화면 | 네레이션 (SecureSara의 언어) |
|---|---|---|
| **0:00–0:15** | Network monitor (Wireshark/fkill) — LibrAgent 사용 중 트래픽 제로 | "LibrAgent를 쓰는 동안, 당신의 데이터는 단 한 번도 네트워크를 나가지 않았어요." |
| **0:15–0:35** | 3개 세션을 동시에 오픈 — 각기 다른 LLM, 다른 MCP 서버, 다른 작업 | "세션 A는 로컬 LLM + 파일 시스템, 세션 B는 온프레미스 RAG + DB, 세션 C는 브라우저 자동화. 모두 격리되어 있어요." |
| **0:35–0:50** | 세션 A에서 민감한 고객 데이터 처리 — 세션 B/C는 전혀 영향 없음 | "세션 A에서 고객 DB를 조회해도, 세션 B의 데이터에는 전혀 접근 못 해요. 이건 설정이 아니라 아키텍처예요." |
| **0:50–1:10** | **Wow Moment:** 세션 격리 UI — 각 세션의 도구 접근 범위가 시각적으로 표시됨 | "각 세션이 어떤 도구, 어떤 파일에 접근하는지 한눈에 보여줘요. 감사 로그도 자동 생성." |
| **1:10–1:30** | 온프레미스 Ollama 연결 + MCP 서버 추가 | "온프레미스 LLM 연결하고, 사내 MCP 서버 추가하고... 끝. 클라우드 의존성 제로." |

**왜 이 시나리오가 잡 hitting인가?**
- SecureSara의 핵심 불안: "내 데이터가 클라우드에 간다"를 **시각적 증거**(네트워크 모니터)로 반박
- 세션 격리를 단순 기능이 아니라 **보안 아키텍처**로 포지셔닝
- 감사 로그 자동 생성 — 엔터프라이즈 컴플라이언스의 핵심 요구사항

**CTA:** "Free로 세션 격리 체험" → "Pro로 무제한 세션 + 감사 로그" → "Enterprise로 SSO + 커스텀 규정"

### 2.3 연구자 ("ResearchRaj") — 멀티에이전트 논문 분석 워크플로우

**페르소나 프로필:** AI/ML 박사 과정, 주 50편 논문 읽음. 메타 분석, 비교 표 작성, 연구 gaps 식별에 주 20시간 소모.

#### 데모 시나리오: "논문 20편을 읽고, 비교표를 만들어줘"

| 시간 | 화면 | 네레이션 (ResearchRaj의 언어) |
|---|---|---|
| **0:00–0:15** | arXiv에서 "Transformer attention 2024" 검색 결과 표시 | "arXiv에서 주제 검색하고, 논문 20편 다운로드." |
| **0:15–0:30** | ResearchAgent 시작 — 각 논문 요약, 핵심 방법론 추출 | "에이전트가 각 논문을 읽고, 방법론, 데이터셋, 결과를 추출해요." |
| **0:30–0:50** | **Wow Moment:** 20편 논문의 비교 표가 자동으로 생성됨 | "20편 논문을 비교하는 표가... 자동으로 만들어져요. 보통 제가 주 20시간 쓰는 작업이죠." |
| **0:50–1:10** | Follow-up 에이전트 실행: "Gaps가 뭐가 있을까?" | "그리고 '연구 gaps는?' 하면, 또 다른 에이전트가 분석해줘요." |
| **1:10–1:30** | 결과물: Markdown 리포트 + CSV 비교표 + 참고문헌 자동 생성 | "Markdown 리포트, CSV, BibTeX까지. 논문 인용도 자동으로." |

**왜 이 시나리오가 잡 hitting인가?**
- "주 20시간" — 연구자의 고통을 숫자로 구체화
- 비교표 자동 생성 — 연구자가 가장 많이 하는 반복 작업의 자동화
- 멀티에이전트: 메인 리서치 에이전트 + Gap 분석 에이전트 → "에이전트가 에이전트를 관리"

**CTA:** "무료로 논문 3편 분석" → "Pro로 무제한 + CSV/Markdown 내보내기" → "팀 구독으로 협업 분석"

## 3. 전환 최적화 관점

### 3.1 Free vs Pro vs Enterprise 명확한 경계

| 기능 | Free | Pro ($19/월) | Enterprise (문의) |
|---|---|---|---|
| **에이전트 실행** | 3회/일 | 무제한 | 무제한 + 커스텀 제한 |
| **동시 세션** | 1개 | 5개 | 무제한 |
| **MCP 서버** | 3개까지 | 무제한 | 커스텀 + 온프레미스 |
| **LLM 제공** | 1개 (로컬) | 5개 (로컬+클라우드) | 커스텀 LLM endpoint |
| **팀/Org 협업** | ❌ | ✅ (5명까지) | 무제한 + SSO |
| **감사 로그** | ❌ | 기본 | 고급 + 커스텀 리포트 |
| **데이터 거버넌스** | ❌ | 세션별 접근 제한 | 역할 기반 + 규정 준수 리포트 |
| **지원** | 커뮤니티 | 이메일 (24h) | 전담 CSM + SLA |

**디자인 원칙:**
- Free는 **"맛보기"가 아니라 "실제 사용"** — 3회/일이면 하루의 대부분의 작업을 커버
- Pro 전환은 **"사용량에 도달했을 때"가 아니라 "다음 단계의 필요성을 느꼈을 때"**
- Enterprise는 **"보안이 필요해졌을 때"가 아니라 "보안이 이미 필요하다는 사실을 알고 있을 때"**

**Waitlist 설계 원칙:**

- Waitlist 가입자에게는 **데모 비디오 3개**를 즉시 보내줌 (value-first)

## 5. 경쟁사 데모 대비 LibrAgent의 시각적 차별점

### 5.1 경쟁사 데모 분석

| 경쟁사 | 데모 스타일 | 강점 | 약점 |
|---|---|---|---|
| **Cursor** | 단일 에이전트 + 코드 편집기 | 코드 편집 경험이 매끄러움 | 단일 에이전트 한계, 클라우드 의존성 |
| **Continue** | VS Code 확장 + 로컬 LLM | VS Code 생태계 통합 | VS Code 전용, 멀티에이전트 없음 |
| **Open Interpreter** | CLI 중심 + 일반 목적 도구 | "Anything-to-code" 철학 | CLI 중심, GUI 없음, 세션 격리 없음 |
| **Dify** | 클라우드 기반 워크플로우 | 워크플로우 시각화 | 클라우드 전용, 온프레미스 제한적 |
| **AnythingLLM** | RAG 중심 데스크톱 앱 | RAG 설정 쉬움 | MCP/멀티에이전트 없음, GUI 단순 |

### 5.2 LibrAgent가 더 "멋져" 보이는 순간들

#### 순간 1: 세션 격리 UI — "에이전트들의 독립적인 세계"

| 경쟁사 | LibrAgent |
|---|---|
| Cursor: 하나의 편집기 창에 하나의 에이전트 | **LibrAgent: Org 뷰에서 3개 세션이 동시에 독립 실행** |
| Open Interpreter: 단일 CLI 세션 | **LibrAgent: 각 세션이 다른 LLM, 다른 MCP 서버, 다른 파일 접근** |
| Dify: 클라우드 워크플로우 캔버스 | **LibrAgent: 데스크톱에서 실시간 세션 격리 시각화** |

**시각적 강점:**
- Org 뷰에서 세션 계보를 트리 구조로 표시
- 각 세션의 도구 접근 범위가 색상으로 코드화
- 세션 간 데이터 흐름이 차단되어 있는 것이 시각적으로 명확

#### 순간 2: MCP 설치 플로우 — "도구 연결의 마법"

| 경쟁사 | LibrAgent |
|---|---|
| Cursor: 내장 도구만, 외부 도구 설정 복잡 | **LibrAgent: MCP 서버를 클릭 한 번으로 추가** |
| Open Interpreter: 수동으로 도구 스크립트 작성 | **LibrAgent: MCP 레포지토리에서 검색 → 설치 → 즉시 사용** |
| Dify: 클라우드에서 도구 API 키 입력 | **LibrAgent: 로컬 MCP 서버 + 클라우드 MCP 서버 통합 관리** |

**시각적 강점:**
- MCP 서버 레포지토리 브라우저 — 카테고리별 필터링
- 설치 진행 상태가 애니메이션으로 표시
- 설치 완료 후 즉시 에이전트 도구 목록에 반영

#### 순간 3: 멀티에이전트 계보 추적 — "누가 뭘 했는지, 완벽하게"

| 경쟁사 | LibrAgent |
|---|---|
| Cursor: 에이전트 히스토리 단일 타임라인 | **LibrAgent: Org 뷰에서 전체 계보 시각화** |
| Open Interpreter: 세션 기록만, 계보 없음 | **LibrAgent: 누가 뭘 결정했는지, 누가 뭘 실행했는지 추적** |
| Dify: 워크플로우 실행 기록 | **LibrAgent: 실시간 세션 격리 + 감사 로그 통합** |

**시각적 강점:**
- Org 뷰에서 에이전트 간 위임 관계를 화살표로 표시
- 각 세션의 실행 기록이 타임라인으로 표시
- 감사 로그가 색상으로 코드화 (작업/실패/권한 차단)

### 5.3 시각적 차별화 요약

```
경쟁사 데모는 "에이전트가 무언가를 한다"를 보여줍니다.
LibrAgent 데모는 "에이전트들이 함께 일하면서, 데이터는 안전하고, 모든 것이 추적된다"를 보여줍니다.

핵심 메시지:
"Cursor는 도구. LibrAgent는 워크스페이스."
```
